# Услуги Ozon по месяцам и магазинам

Суммы услуг — строки начислений Ozon с его типами (`type_id`) и именами. Seller AI отдаёт их помесячно в отчёте о прибыли: никаких
перебежек по 30 дней, файлов прогресса и повторов — один запрос на магазин и год.

## Какая услуга

Сначала понять, о какой строке Ozon речь. Частые (тип — имя Ozon — категория отчёта о прибыли):

| `type_id` | Услуга | Категория |
|---|---|---|
| 18 | Досрочная выплата (`EarlyPayment`: разовая и еженедельные выплаты) | `payouts` |
| 20 | Гибкий график выплат (`FlexiblePayments`: ежедневные выплаты) | `payouts` |
| 1, 22 | Эквайринг, рассрочка | `acquiring` |
| 32, 29, 98, 16, 17 | Логистика, последняя миля, доставка до места передачи, обработка отправления (Drop-Off) | `logistics` |
| 59, 45, 6 | Обратная логистика, обработка возврата в ПВЗ, отмены | `returns_logistics` |
| 41, 54 | Оплата за клик, «Продвижение товара» (оплата за заказ) | `advertising` |
| 74, 95, 96, 116 | Звёздные товары, отзывы | `advertising` |
| 12, 77, 97 | Кросс-докинг, приёмка и обработка поставки | `supply_storage` |
| 46, 78, 79 | Размещение (хранение), временное размещение | `supply_storage` |
| 38, 39, 84 | Упаковка | `supply_storage` |
| 71 | Вывоз со склада | `supply_storage` |
| 76 | Страхование остатков (Ozon отменил с 13.10.2026) | `supply_storage` |
| 15, 103 | Утилизация, утилизация отправления | `disposal` |
| 52, 127, 24 | Подписка Premium, «Аналитика+», клонирование карточки | `subscriptions` |
| 93, 94 | Штрафы за ошибки и опоздание отгрузки | `fines` |
| 25, 57, 72 | Компенсации, корректировки, взаимозачёт | `compensations` |

Точное имя и id в магазине — в `categories[].types[]` ответа `economics_profit_get` (имя Ozon, `type_id`, `key`). Не нашли — поиск
по строкам: `finance_accruals_list` с `search` за период.

**Выплаты не путать.** «Досрочная выплата» (18) и «Гибкий график выплат» (20) — разные услуги, суммы различаются в разы. Спросили
«досрочную выплату» — показать 18 и рядом 20 (их часто считают одним). Ставка обеих — процент от суммы, которая приходит на счёт
(например, 100 000 ₽ × 3,74 % = 3 740 ₽), своя у каждого магазина и меняется; Seller API её не отдаёт. В Seller AI её вводит
продавец: `stores_economics_settings_get` → `early_payout_rate` (доля выплаты на счёт, действует с `effective_from`; версии по
датам — `stores_economics_settings_list`); не задана (`null`) — Seller AI берёт автоматическую по начислениям 18 и 20 за 28 дней
(`auto.early_payout_rate` в `stores_economics_settings_list`). Показывать ставку рядом с суммами 18 и 20 и говорить, какая она:
введённая с даты X или автоматическая.

**Не услуги, а движение денег** — «Займы и факторинг» и «Зачислено в периоде» (пополнения баланса): их нет среди начислений и в
`types` отчёта о прибыли — это не 0 ₽. Суммы — `balance_incomes_list` за месяц (`from`, `to`; узлы `tree` с `id`
`loans_and_factoring` и `incoming_payments`), по запросу на месяц; загружен ли «Баланс» — `stores_history_months_get` с
`feature=store_balance`.

## Порядок

1. `stores_list` — все магазины или названные пользователем.
2. По каждому магазину — `stores_history_months_get` с `feature=store_economy`: `bounds.from` — первый день, с которого у Seller AI
   есть начисления, `months[]` — `ready` или `loading`. «За всё время» начинается с `bounds.from` (не раньше 2022-01-01). В ответе
   назвать месяц первых данных: иначе неясно, 0 — это «не пользовались» или «не смотрели».
3. Суммы по месяцам — `economics_profit_get` с `group=month` за весь период одним запросом (`from`, `to`): в `series[]` у каждого месяца
   `types` — суммы по ключу строки, для типа Ozon ключ = его `type_id` строкой (`"18"`). Расход — со знаком минус; показывать по
   модулю с пометкой «расход». Схема — `scheme=all` (услуги без отправления есть только там).
4. Нужны строки (дата, отправление, поставка) — `finance_accruals_list` с `type_id` (или `type_ids` через запятую) за период,
   постранично; `total` — число строк.

## Что говорить вместо нуля

- 403 `forbidden` — «нет доступа к магазину в Seller AI», не 0 ₽.
- 409 `not_ready`, `sync_pending`, месяц `loading` — «ещё загружается».
- Месяц раньше `bounds.from` — «нет данных», а не 0.
- **Ключ Ozon отозван или истёк** — `stores_ozon_access_get`: предупреждение `seller_key_invalid` или `seller_key_expired`
  (`since` — с какого момента). Новые начисления тогда не загружаются: месяцы после последней удачной загрузки (`streams[]` /
  `quality` ответа `economics_profit_get`, `last_success_at`) — «нет данных: ключ Ozon магазина не работает», не 0;
  предложить перевыпустить ключ.
- Строки услуги в загруженном месяце нет — тогда 0 ₽ (услугу не списывали); движения денег (выше) — только по «Балансу».

## Формат

Таблица «месяц × магазин» (или «магазин × месяц» при многих магазинах) с суммой по модулю, строка ИТОГО, первый месяц данных каждого
магазина. Для выплат — две колонки: досрочная (18) и гибкий график (20).
