# Комплекты из готовых Super-заявок

Вход: магазин, точный SKU и фасовка, целое количество. Название сначала однозначно сопоставить с SKU (`products_list` с
`search`); похожую фасовку не подставлять. Здесь заявки **не создаются и состав не меняется** — только выбор целых
поставок, таймслот и этикетки.

## Правила отбора

- **Атом — целая поставка** (кластер) заявки: весь её товар, все её грузоместа, все этикетки. Можно взять часть поставок
  многокластерной заявки. Поставку со смешанными SKU не брать — разделить её нельзя.
- Пригодна поставка `READY_TO_SUPPLY` заявки с меткой Super (`order.tags.super = true` — это `product_super_fbo` заявки;
  подключение продавца к Super её не заменяет), с грузоместами, состав каждого из которых прочитан и в сумме равен
  количеству поставки. Текущий Super карточки — отдельный признак: его отсутствие не исключает старую Super-заявку.
- **Точное количество обязательно.** Ближайшее — только с решения пользователя. Повторы кластеров разрешены; запрет
  пользователя — `allow_repeats: false`.
- Приоритеты: точная сумма → больше начатых заявок, взятых до конца → больше штук из начатых заявок → больше разных
  кластеров → меньше новых заявок → меньше поставок. «Начатая» — заявка, часть поставок которой уже отгружена (статус
  дальше `READY_TO_SUPPLY`), а часть ещё ждёт.
- Метка Super — не денежный расчёт: суммы прогноза доставки в Seller AI нет. Просят «бесплатные» — бесплатность каждой
  выбранной заявки и её слота сверяется в кабинете Ozon; без сверки не называть комплект бесплатным, неизвестная
  стоимость — не ноль. Прогноз 0 ₽ — не гарантия отсутствия других начислений.

## Порядок

1. **Кандидаты.** `supplies_items_list` с `sku`, `super=true`, `states=READY_TO_SUPPLY,ACCEPTED_AT_SUPPLY_WAREHOUSE,IN_TRANSIT`
   (все страницы по `offset`) → Super-заявки с этим SKU и кластер каждой поставки; по каждой `supplies_orders_get`. Затем
   ```bash
   python3 scripts/kits_select.py rows in.json   # {"sku", "orders": [ответы supplies_orders_get], "now": "<сейчас, UTC>"}
   ```
   → `rows` (поставка, заявка, кластер, штуки, размеры мест, `started`, таймслот) и `rejected` с причинами (не Super,
   статус, смешанный состав, нет мест, места не сходятся, таймслот прошёл). `sync_pending` / `composition_complete: false`
   — состав не прочитан: так и сказать.
2. **Уже выданное.** Учёта выданных этикеток и зарезервированных комплектов в Seller AI нет: спросить пользователя, какие
   поставки уже взяты в комплекты и ещё не отгружены (или взять из этого разговора), и передать их в
   `exclude_supply_ids`. Отгруженные поставки и так выпадают по статусу.
3. **Подбор.**
   ```bash
   python3 scripts/kits_select.py select in.json   # {"rows", "target", "allow_repeats", "exclude_supply_ids"}
   ```
   → выбранные поставки, сколько из начатых заявок и сколько добрано, кластеры и повторы, `started_leftovers_not_taken`.
   `proven: false` — оптимальность не доказана за предел шагов: сказать это и предложить сузить кандидатов. Точной
   комбинации нет — назвать ближайшие достижимые суммы и спросить.
4. **Показать и спросить.** Точная сумма; по городам — штуки, коробки (`units_per_place`), заявка ссылкой; сколько из
   начатых заявок и сколько добрано; оставшийся свободный остаток каждой взятой заявки; почему отложенные остатки не вошли
   (нет точной комбинации / приоритет / недоступны по Ozon). Ничего не менять до «да».
5. **Свежая проверка перед выдачей.** Снова `supplies_orders_get` по выбранным заявкам: статус, количество, слот, весь
   список мест и состав каждого — как при подборе. Изменилось — остановиться и подобрать заново.
6. **Таймслот.** У выбранной заявки нет слота или он не подходит пользователю — навык `supplies-orders`
   (`supplies_orders_timeslots_list` → `supplies_orders_timeslot_set`). С первым таймслотом Ozon считает «Точность
   отгрузок» по **всем** поставкам заявки: поставки, не отгруженные к этому слоту, посчитаются как непривезённые — 0 из
   максимума. Если берутся не все поставки заявки, сказать это до выбора слота.
7. **Этикетки.** PDF каждой выбранной поставки — `supplies_cargo_labels_download` (`order`, `supply`) — PDF этикеток грузомест одной поставки, файлом в ответе. Пока Ozon готовит файл, ответ — JSON с `task_id`: через несколько секунд повторить вызов с тем же `order`, `supply` и этим `task_id`. Назвать, какие
   поставки (города) печатать по каждой заявке и сколько мест каждого размера: печатать только выбранные. Разложить PDF по
   размерам коробок агент сейчас не может.

## Ответ

Точная сумма, число уникальных и повторных кластеров, заявки ссылками `[<order_number>](https://seller.ozon.ru/app/supply/orders/<order_id>)`,
даты слотов (время точки отгрузки), грузоместа по городам, частично взятые заявки и их остаток, отложенные остатки с
причиной. Отменённые, просроченные и пропавшие остатки — отдельно, не как отгруженные. Не обещать бесплатность без
сверки. Физическая отгрузка — отдельное подтверждение пользователя; выдача этикеток — не отгрузка.
