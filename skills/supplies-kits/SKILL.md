# Комплекты из готовых Super-заявок

Вход: магазин, точный SKU и фасовка, целое количество. Название сначала однозначно сопоставить с SKU (`products_list` с
`search`); похожую фасовку не подставлять. Здесь заявки **не создаются и состав не меняется** — только выбор целых
поставок, таймслот и этикетки. Пользователь передумал брать из поданных («с нуля», «всё новой заявкой») — навык
`supplies-create`, шаг 0, п. 6: весь объём — в новый план, отмена прежних заявок — только явным «да».

## Правила отбора

- **Атом — целая поставка** (кластер) заявки: весь её товар, все её грузоместа, все этикетки. Можно взять часть поставок
  многокластерной заявки. Поставку со смешанными SKU не брать — разделить её нельзя.
- Пригодна поставка в статусе `READY_TO_SUPPLY` — статус самой поставки (`supply_state`), а не заявки: у частично
  отгруженной заявки (`IN_TRANSIT`, `ACCEPTANCE_AT_STORAGE_WAREHOUSE`, `REPORTS_CONFIRMATION_AWAITING`) готовые поставки
  тоже пригодны и считаются. Заявка — с меткой Super (`order.tags.super = true` — это `product_super_fbo` заявки;
  подключение продавца к Super её не заменяет), с грузоместами, состав каждого из которых прочитан и в сумме равен
  количеству поставки. Текущий Super карточки — отдельный признак: его отсутствие не исключает старую Super-заявку.
- Только заявки той точки отгрузки (или того же города), откуда пользователь везёт: `dropoff_ids` в `rows`; остальные —
  в `rejected` с причиной. Точку не сверили — так и сказать в ответе.
- **Точное количество обязательно.** Ближайшее — только с решения пользователя. Повторы кластеров разрешены; запрет
  пользователя — `allow_repeats: false`.
- Приоритеты: точная сумма → больше начатых заявок, взятых до конца → больше штук из начатых заявок → больше разных
  кластеров → меньше новых заявок → меньше поставок → при равенстве — более ранний слот. «Начатая» — заявка, часть
  поставок которой уже отгружена (статус
  дальше `READY_TO_SUPPLY`) или уже взята в комплекты (`exclude_supply_ids`), а часть ещё ждёт.
- Метка Super — не денежный расчёт: прогноза стоимости доставки нет ни в Seller AI, ни в API Ozon. Просят «бесплатные» —
  бесплатность каждой выбранной заявки и её слота сверяется в кабинете Ozon; в ответе назвать, что и когда сверено
  (заявка, слот, время сверки); сверка годна сутки и только для того же слота — слот или состав поменялись, сверить
  заново; без сверки не называть комплект бесплатным, неизвестная стоимость — не ноль. Прогноз 0 ₽ —
  не гарантия отсутствия других начислений. Факт — после приёмки: `finance_accruals_list` с `search=<supply_id>` и
  `search_scope=all` по каждой поставке комплекта.

## Порядок

Просят только посчитать («сколько у меня готово к отгрузке») — шаг 1 и итог: поставки, штуки, коробки по фасовке и заявки, в которых они лежат (любого статуса заявки), — без подбора, слотов и этикеток.

1. **Кандидаты.** `supplies_items_list` с `sku`, `super=true`, `supply_states=READY_TO_SUPPLY` — статус самой поставки
   (`states` — статус заявки: начатые заявки в `ACCEPTANCE_AT_STORAGE_WAREHOUSE`, `REPORTS_CONFIRMATION_AWAITING` иначе
   выпадут, а подбор берёт их первыми); все страницы по `offset` → Super-заявки с этим SKU и кластер каждой поставки; по
   каждой `supplies_orders_get` (все её поставки — из них видно, что заявка начата). Затем
   ```bash
   python3 scripts/kits_select.py rows in.json   # {"sku", "orders": [ответы supplies_orders_get], "now": "<сейчас, UTC>",
                                                 #  "dropoff_ids": [точки отгрузки, откуда везут]}
   ```
   → `rows` (поставка, заявка, кластер, штуки, размеры мест, `started`, таймслот, точка) и `rejected` с причинами (не
   Super, статус, смешанный состав, нет мест, места не сходятся, таймслот прошёл, другая точка отгрузки).
   `sync_pending` / `composition_complete: false` — состав не прочитан: так и сказать.
2. **Уже взятое.** Только из этого разговора, без вопросов: поставки, уже взятые в комплекты в нём, и те, что
   пользователь сам назвал взятыми, — в `exclude_supply_ids`. Истории нет — ничего не спрашивать и ничего не исключать:
   свободна каждая поставка «Готово к отгрузке» (`READY_TO_SUPPLY`), в многокластерной заявке — каждая по своему
   статусу; отгруженные и так выпадают по статусу. Взятое нигде не записывать (ни в файлы, ни в заметки, ни в память
   агента) и не просить пользователя вести такой список.
3. **Подбор.**
   ```bash
   python3 scripts/kits_select.py select in.json   # {"rows", "target", "allow_repeats", "exclude_supply_ids"}
   ```
   → выбранные поставки, сколько из начатых заявок и сколько добрано, кластеры и повторы, `started_leftovers_not_taken`.
   `proven: false` — оптимальность не доказана за предел шагов: сказать это и предложить сузить кандидатов. Точной
   комбинации нет — назвать ближайшие достижимые суммы и спросить. Несколько объёмов сразу («6000 и 3000») —
   `"targets": [6000, 3000]` вместо `target`: непересекающиеся комплекты, по порядку пользователя, а если так не
   выходит — в другом (`order_used`); подобрать все до слота первого.
   **По потребности** («возьми из поданных по потребности»): потребность по кластерам — `supplies_planning_availability`
   (`recommended_supply`) или план навыка `supplies-create`; затем
   ```bash
   python3 scripts/kits_select.py by_need in.json   # {"rows", "need": [{"cluster_id", "name", "need", "ads"}], "exclude_supply_ids"}
   ```
   → на нуждающийся кластер одна целая поставка (наименьшая не меньше потребности, иначе наибольшая), перебор в днях
   запаса (`over_days`), недобор и кластеры без поставок (`missing`) — остаток новой заявкой (`left_for_new_order`).
   Показать по городам «берём N шт (K кор.) при потребности M» и вариант «этот город не брать, подать новой заявкой».
4. **Показать подбор.** Точная сумма; по городам — штуки, коробки (`units_per_place`), заявка ссылкой; сколько из
   начатых заявок и сколько добрано; оставшийся свободный остаток каждой взятой заявки; почему отложенные остатки не вошли
   (нет точной комбинации / приоритет / недоступны по Ozon). Подбор ничего не меняет. Дальше — только команда таймслота:
   просьба с объёмом и датой («6000 шт на 05.11») — согласие поставить слот (шаг 6), кроме случая, когда у взятой заявки
   берутся не все поставки (точность, шаг 6) или точной суммы нет — тогда спросить один раз.
5. **Свежая проверка перед выдачей.** Снова `supplies_orders_get` по выбранным заявкам: статус, количество, слот, весь
   список мест и состав каждого — как при подборе. Изменилось — остановиться и подобрать заново.
6. **Таймслот.** У выбранной заявки нет слота или он не подходит пользователю — навык `supplies-orders`
   (`supplies_orders_timeslots_list` → `supplies_orders_timeslot_set`). С первым таймслотом Ozon считает «Точность
   отгрузок» по **всем** поставкам заявки: поставки, не отгруженные к этому слоту, посчитаются как непривезённые — 0 из
   максимума. Если берутся не все поставки заявки, сказать это до выбора слота и спросить.
7. **Этикетки** — только выбранные поставки, одним набором: `supplies_cargo_labels_bundles_create` (`body: {supplies:
   [{order_id, supply_id}]}` — каждая выбранная поставка, без `cargo_ids`: все её живые места; `names: {<sku>:
   «<название с весом>»}` — когда пользователь называет товар иначе, чем карточка; один `idempotency_key`) → 202 с
   `bundle_id` → `supplies_cargo_labels_bundles_get` (`bundle`): 202 `working` — повторить через `retry_after`; 200
   `ready` — `files[]`, каждый файл — `supplies_cargo_labels_bundles_file` (`bundle`, `file`). PDF на вид места по всему
   комплекту: «<товар> <N> коробок по <X> шт.pdf» / «<товар> <N> палет по <X> шт.pdf». **Все файлы — пользователю сразу,
   имена не менять**; `missing` (места без этикеток и почему) — назвать прямо; страниц в файле — `pages` = `places`.
   Набор живёт сутки. Запасной путь — одна поставка: `supplies_cargo_labels_download` (`order`, `supply`; JSON с
   `task_id` — повторить с ним через несколько секунд), выбранные места — навык `supplies-cargoes`, «Этикетки» (на каждой
   странице — номер места из задания).

## Ответ

Точная сумма, число уникальных и повторных кластеров, заявки ссылками `[<order_number>](https://seller.ozon.ru/app/supply/orders/<order_id>)`,
даты слотов (время точки отгрузки), грузоместа по городам, по каждому файлу этикеток — города и число мест, частично
взятые заявки и их остаток, отложенные остатки с причиной. Одной фразой — откуда известно уже взятое: из этого
разговора или только по статусам поставок (свободна каждая «Готово к отгрузке»). Отменённые, просроченные и пропавшие остатки — отдельно, не как отгруженные. Не обещать
бесплатность без сверки. Физическая отгрузка — отдельное подтверждение пользователя; выдача этикеток — не отгрузка.
