# Комиссии Ozon по категориям

Два источника, по порядку точности:

1. **Ставка карточки магазина** — то, что Ozon отдаёт в карточке сейчас, уже с индивидуальными условиями (ИУ) магазина. Для
   существующего товара — только она.
2. **Справочник Ozon** `references/commissions-2026-08-28.tsv` — «Таблица категорий и типов для расчёта вознаграждения с 28 августа
   2026 г.» из «Комиссий и тарифов» Базы знаний, 9 308 строк. Для нового товара без карточки и для сверки.

## Ставка товара магазина (Seller AI)

- **По товару** — `unit_economics_plan_list` (`scheme=FBO` или `FBS`): у строки `inputs.commission_micro` (цена ≤ 100 ₽),
  `commission_low` (100–300 ₽), `commission_high` (> 300 ₽) — доли (`0.4` = 40 %), `commission_rate_manual` — ручная ставка на любую
  цену, если задана; `sources.commission_*` — откуда: `api_commission` (ставка карточки Ozon), `store_rule` (правило ИУ магазина),
  `store_rates` (одна ставка магазина во всех диапазонах), `category_table` (справочник); `basis` — диапазон, цена, число карточек;
  `commission_tariff` — строка справочника категории карточки (`main_category`, `category_name`, `type_name`). Предупреждение
  `commission:no_rate` — ставки нет нигде. Шаг `computed.commission_rate` — ставка при цене плана.
- **По магазину** — `stores_commission_rules_list`:
  - `detected[]` — что Ozon отдаёт в карточках сейчас: по схеме (`FBO`, `FBS`) и диапазону (`micro` ≤ 100, `low` ≤ 300, `high` > 300)
    — ставки с числом карточек. **Одна ставка во всех диапазонах — признак ИУ** (вживую 22.10.2026: у двух магазинов 22 % на
    любую цену, у остальных 17 / 23 / 40 %, у одного 22,78 / 39,78 %);
  - `rules[]` — ИУ, записанные в Seller AI: схема, категория (или все), цена `(price_from, price_to]`, ставка, с даты. Из правил одного
    товара действует последнее по дате, среди правил одного дня — самое узкое;
  - `categories[]` — категории и типы живых карточек магазина (`description_category_id`, `type_id`, путь); `ozon.tax_system`,
    `ozon.vat`.
- **В рублях при текущей цене** — `prices_products_list` (`tab=expenses`): `expenses.base` — цена с акциями продавца, от которой Ozon
  считает вознаграждение, `fbo` / `fbs` / `rfbs` — расходы схемы (вознаграждение + эквайринг + логистика) в рублях, как кабинет.

Ставка фиксируется **по дате заказа**: в начислениях недели видна смесь ставок (у одного магазина 24 % до 14.09, затем 40 / 23 %, с ~12.10 —
22 %). Факт удержаний — `unit_economics_accruals_list` (`amounts.commission` товара) и `finance_accruals_list` (у строки продажи
`children[].commission_ratio` «Вознаграждения за продажу» — ставка, которую Ozon применил, долей).

## Справочник для нового товара

Файл — TSV в UTF-8, первая строка — заголовки: «Основная категория», «Категория», «Тип товара», затем ставки **в процентах**:
FBO до 100 / 100–300 / свыше 300, FBO Fresh (три диапазона), FBS (три диапазона), RFBS, RFBS мототехника свыше 500 тыс. Пустая
ячейка — у Ozon ставки нет.

Поиск — по подстроке без регистра в «Категории» и «Типе товара»:

```sh
grep -i "сухофрукт" references/commissions-2026-08-28.tsv
grep -i -P "\tКонфеты\t" references/commissions-2026-08-28.tsv     # точный тип
cut -f2 references/commissions-2026-08-28.tsv | sort -u              # все категории
```

Не нашлось — родственные слова (сушёный → сухофрукты, конфеты → конфета), затем категория выше. Диапазон — по цене продавца с его
акциями: ≤ 100 ₽, 100–300 ₽ (выше 100 и до 300 включительно), > 300 ₽. Ответ — ставка в процентах и в рублях (`цена × ставка`) со
строкой справочника.

## Факты Ozon

- **С 28.08.2026** у товаров дороже 300 ₽ одна ставка на основную категорию (продукты питания — 40 %; было 31–37 % по диапазонам
  300–500 / 500–1500 / > 1500); дешёвые — почти везде 17 % (до 100 ₽) и 23 % (100–300 ₽), было 14 / 20 %. Переход цены через
  100 / 300 ₽ меняет ставку сразу.
- Тариф «Эконом» (кванты) Ozon отменил с 31.03.2026: флага «эконом» у карточки нет, «эконом» в речи продавцов — нижние диапазоны.
- «Благотворительность» в справочнике — 1 %, но без верификации НКО Ozon берёт обычную ставку категории (по API и начислениям — 40 %).
- Ozon объявил новую таблицу вознаграждений с 07.10.2026 и отмену баллов за скидки с новой формулой вознаграждения с 01.12.2026; файл
  этих версий ещё не загружен: для нового товара сказать, что ставка — по таблице от 28.08.2026, и сверить с калькулятором кабинета.

## Индивидуальные условия (запись, с согласием)

`stores_commission_rules_save_many` **заменяет весь набор** правил магазина (до 1 000): прислать все прежние (с их `id`) и новое.
Показать таблицу «правило: схема, категория, цена, ставка, с даты — было → станет», записать после «да». Это наши данные (план и
факт пересчитаются), в Ozon ничего не уходит. ИУ задают, когда их не видно из API: будущая дата соглашения, отдельные категории.
