# Юнит-экономика

План и факт считает Seller AI: агент читает посчитанное, объясняет и сохраняет правки. Скрипты — только для обратных вопросов
(`scripts/plan_solve.py`) и товара, которого ещё нет в Ozon (`scripts/new_product_plan.py`).

## План по товарам

`unit_economics_plan_list` (`scheme=FBO` по умолчанию или `FBS`; обычно нужен `status=in_sale`, без него — все строки). Строка —
карточка × схема, статистика — главного SKU:

- `computed` — шаги на **выкупленную** единицу (`margin` — к цене, `profitability` — к себестоимости); `inputs` — входы (ручные поверх
  авто), `overrides` — ручные в силе, `sources` и `basis` — откуда авто-значение;
- `cluster_details[]` (FBO) — вес кластера назначения, доля локального тарифа `local_share`, локальный и нелокальный тарифы,
  остаток и запас в днях; `inputs.logistics_overpay` — переплата против локальных тарифов, включая запас на ошибку;
- `basis.logistics_lt_300/gte_300` — запас в рублях `margin` и п.п. `margin_share`, доля локального тарифа до запаса `local_share`,
  `stock_units`, `cover_days`, `shares_source` (`seller_ai_orders` — по заказам магазинов Seller AI за 28 дней; `ozon_file` — резерв
  из файла Ozon). Без остатка и со своими начислениями — ещё `sample` единиц за `window_days`, `nonlocal_share`;
- `warnings` (`cost:missing`, `cost:ozon_net_price`, `commission:no_rate`, `supply:no_accruals_yet`, `buyout:store_prior`,
  `buyout:category`, `missing:<вход>`); `coverage.incomplete_rows` — строки без прибыли;
- `ozon_prices` — цены карточки в Ozon, `actions` — акции, `in_scheme {stock, sold_28d}` — продаётся ли по схеме, `revision` — для
  сохранения.

### Формула v5 (на выкупленную единицу)

`P` — цена с акциями продавца (`marketing_seller_price` больше 0, иначе `price`, но не выше `price`); `B` — выкуп; `c₀` — отмены до
отгрузки; `u` — доля утилизированных (`disposal_share`).

| Шаг | Формула |
|---|---|
| Вознаграждение | `P × ставка` диапазона цены: ≤ 100 ₽ `commission_micro`, ≤ 300 ₽ `commission_low`, выше `commission_high`; ручная `commission_rate_manual` — на любую цену |
| Эквайринг | `P × acquiring_rate` |
| Логистика с невыкупами | `(Л + М) / B + (1 − B) / B × (Л_обр + обработка)`; `Л` — тариф бакета цены (≤ 300 ₽ `logistics_lt_300`, выше `logistics_gte_300`), `М` — последняя миля и обработка отправления |
| Прочее Ozon | кросс-докинг (FBO), размещение, `u × disposal_fee`, `P × stars_rate`, `P × insurance_rate`, прочие сборы |
| Реклама | `P × ДРР / ((1 − c₀) × B)`; ДРР — целевой, к выручке заказов |
| Выплата Ozon | `P − ИТОГО Ozon − реклама` |
| Досрочная выплата | `выплата × r / (1 + r)` (комиссия с суммы, которая приходит на счёт); выплата ≤ 0 — 0 |
| Доход, НДС | доход — `P × (1 − баллы)` при базе `revenue` и `profit` (баллы за скидки = ставка вознаграждения строки), `P` при `sales`; НДС = `доход × НДС / (1 + НДС)` |
| Налог | `ставка × (доход − НДС)`; при базе `profit` — от прибыли до налога; база ≤ 0 — 0 |
| **Прибыль** | `выплата − досрочная − себестоимость − u × себестоимость − прочие расходы − НДС − налог` |

Цена перешла через 100 или 300 ₽ — сразу меняются ставка и бакет логистики.

### Откуда авто-входы

- Выкуп и отмены — зрелые когорты заказов 90–14 дней назад. Мало своих заказов — выкуп по типу товара (`buyout:category`), затем по
  магазину (`buyout:store_prior`), иначе 0,93. Последняя миля, обратная логистика, эквайринг, утилизация, прочие сборы — по
  начислениям за 28 / 90 дней; кросс-докинг — по принятым поставкам остатка.
- Логистика FBO — матрица с 30.10.2026: доля локального тарифа зависит от запаса в днях на 14 дней вперёд, остальное — из
  ближайшего кластера с остатком. Запас на ошибку — 25 / 19 / 14 / 8 п.п. при остатке <500 / <1000 / <3000 / от 3000 шт.
  Веса — общие заказы магазинов Seller AI за 28 дней (меньше 1000 отправлений — доли Ozon), поверх — свои единицы с весом
  `N / (N + 300)`. Без остатка — свои начисления за 28 дней (90, если меньше 10 единиц), иначе локальные тарифы; запас 25 п.п.
  Средние логистики магазина и универсальный тариф не применяются. Матрица 28.08 нужна только для распознавания старых начислений
  по заявкам, фиксирующим тариф на 60 дней.
- Ставка вознаграждения — правило ИУ магазина → ставка карточки Ozon → частая ставка магазина в категории и диапазоне → справочник
  категорий.
- «Звёздные товары» и досрочная выплата — из настроек магазина, иначе по начислениям; баллы за скидки равны ставке вознаграждения. В
  строке все три не правятся: `stars_rate`, `early_payout_rate`, `points_share` в `overrides` — 422. Размещение — 0, пока не задано.
- **Целевой ДРР не рассчитывается:** его задаёт продавец (не задан — 0, источник `not_set`). Отправная точка — фактический общий ДРР
  товара за 28 закрытых дней: `promotion_analytics_get` (`slice=product`, `skus`; `metrics.drr` — проценты; `gmv.covered: false` —
  неизвестен). Предложить его и сохранить, когда пользователь согласен или сам просит «поставь ДРР как по факту».

## Сценарии без записи

- «Что будет при цене X / ДРР Y / выкупе Z» — `unit_economics_plan_preview` (`scheme`, `product_id`, `price`, `drr`,
  `cost {value, effective_from}`, `overrides`): строка с черновиком поверх сохранённого, ничего не пишет.
- Обратные вопросы («какая цена даст 50 ₽ прибыли или 30 % рентабельности», «до какой себестоимости товар в плюс», таблица
  вариантов): ответ `unit_economics_plan_list` (или строку `unit_economics_plan_preview`) сохранить в файл и запустить
  `python3 scripts/plan_solve.py --row plan.json --product <product_id> --solve price --target-profit 0,20,50`
  (или `--target-margin`, `--target-profitability` — долями; `--solve cost` — предельная себестоимость; `--price` / `--cost` — при
  другой цене или себестоимости). Цена перебирается по рублю: на 100 и 300 ₽ прибыль прыгает, скрипт скажет, где цель снова теряется.
  Затем один `unit_economics_plan_preview` с найденной ценой (или себестоимостью) — в ответ его цифры. Найденная цена — `P`, с акциями
  продавца. Новый товар — то же по выводу `new_product_plan.py --json`.

## Сохранить план

`unit_economics_plan_save_many` (`scheme`, `items[{product_id, expected_revision, price?, drr?, cost?, overrides?}]`) — только
изменённые поля; `drr` — доля (`0.12`); `null` возвращает цену к цене карточки, ДРР — к «не задан», ручное значение — к авторасчёту.
Ручные значения свои у схемы, `other_unit_cost` — общий.

- Полная просьба («поставь курагам ДРР 12 %») — согласие: сохранить и показать «было → стало» с пересчитанной прибылью.
- «Что будет, если…» — только preview, без записи. Неясно, какой товар или схема, — спросить один раз.
- `conflicts[{product_id, revision}]` — товар изменили после чтения: перечитать и показать заново.
- Цель биддера «ДРР из плановой юнит-экономики» подхватывает новый ДРР сразу.

## Цена в Ozon

Цена плана `P` — с акциями продавца, а в Ozon меняется `price` («Предельная цена без акций»): `prices_values_set`
(`items[{product_id, price, old_price, min_price, expected {price, old_price, min_price}}]`; цены — строки рублей `"259.00"`, `expected`
— из `ozon_prices` строки). Показать «сейчас → новая» и предупредить: покупатели увидят цену сразу, могут измениться индекс цен,
участие в акциях и цена с акциями. Полная просьба («поставь 259 ₽») — согласие, иначе спросить один раз. Больше 50 % — только владелец
(`can_change_large` в `prices_summary_get`), каждый раз с `confirm_large_change: true` после отдельного «да». Включена «Минимальная
цена = Ваша цена» (`prices_automation_get`) — `min_price` не менять. 403 `large_change_owner_only` — не повторять, это сделает
владелец; 409 `stale_expected` — цена уже другая: перечитать и показать заново; остальное — навык `product-management`, «Изменить
цену». Цену с акциями Ozon пересчитает сам (~15 минут), план увидит её после чтения цен.

## Факт по товарам

- «По начислениям» — `unit_economics_accruals_list` (`from`, `to`, `scheme`, `allocate`): прибыль товара за период, сходится с итогом
  магазина (навык `net-profit`). С планом сравнивать на единицу: `accrued / units.net` против `computed.payout`, `profit_per_unit`
  против `computed.profit` — план на выкупленную единицу, факт на нетто проданную.
- «Как в Ozon» — `unit_economics_actual_get` (`from`, `to`, `scheme`, `sku`, `search`): копия раздела кабинета с его прибылью.

## Себестоимость

- По периодам — `cost_prices_list` (`search`): `current {cost, effective_from, source}`, `previous`, `periods`; `ozon_net_price` 0 — «не
  задана», не ноль. Записать — `cost_prices_save_many` (`changes[{product_id, effective_from, cost}]`, `cost: null` удаляет период):
  период действует со своей даты до следующего, прошлые дни пересчитываются. Себестоимость с датой («курага 400 — 180 ₽ с 01.10») —
  согласие: записать и показать «товар — было → стало — с даты»; дата не названа — спросить один раз (с сегодня или с другой).
- Из Excel («ID товара», «SKU» или «Артикул», «Себестоимость», по желанию «Действует с») — `uploads_create` (`purpose: "workbook"`) →
  `cost_prices_import` (`body {"upload_id": "…"}`; по умолчанию `dry_run` — показать `summary` и строки `new` / `change` / `error`) →
  с согласия тот же `upload_id` с `dry_run=false`. Таблица для правки — `cost_prices_export`.
- По партиям поставок (эксперимент, только FBO) — `cost_batches_list`: без `sku` — сводка (`difference` — расхождение журнала с остатком
  Ozon), с `sku` — партии, журнал и себестоимость проданного по периодам и по партиям. Цена партии — `cost_batches_save_many`
  (`changes[{supply_id, sku, unit_cost}]`, `null` — к цене периода) по полной просьбе или после «да».

## Настройки экономики магазина

`stores_economics_settings_list` — версии с датами (`in_force` — действующая сегодня, `auto` — что план берёт для пустых «Звёздных» и
досрочной); `stores_economics_settings_get` — действующая сегодня. Ставки — доли (`0.06`): `tax_rate`, `tax_base` (`revenue` | `sales` |
`profit`), `vat_rate` (0, 5, 7, 10 или 22 %), `stars_rate` (доля цены), `early_payout_rate` (доля выплаты на счёт: своя у магазина, видна
в кабинете, Seller API её не отдаёт; стандартный график — 0). Ещё `cost_method` (периоды или партии), `other_unit_cost` (упаковка,
маркировка, доставка до склада, ₽ на единицу), `default_buyout`.

Записать версию — `stores_economics_settings_save`: `effective_from`, `packaging_quality`, `default_buyout`, `flat_commission` взять из
версии, действующей на эту дату; поле, которого нет в теле, остаётся прежним, `null` очищает. Версия с прошлой даты пересчитает налог и
прибыль прошлых дней. Удалить — `stores_economics_settings_delete` (`effective_from`): снова действует предыдущая. Обе — по полной
просьбе (значение и дата названы) или после «да»; в ответе — какие дни пересчитаются.

Индивидуальные условия по вознаграждению — `stores_commission_rules_list` / `stores_commission_rules_save_many`, навык
`category-commissions`.

## Новый товар без карточки

Seller AI считает только карточки магазина. Для идеи товара — `scripts/new_product_plan.py`: та же формула v5
(`references/plan-formula.schema.json`), локальные тарифы FBO с 30.10.2026 из `references/logistika-fbo-fbs.xlsx` с запасом 25 п.п.
на ближайший другой кластер. Остатка и собственных начислений у нового товара нет. Универсальный тариф не используется.
Доли — резерв из файла Ozon (`references/cluster_market_share_defaults.json`): общие доли заказов магазинов Seller AI офлайн
недоступны. Назвать это ограничение; не выдавать расчёт за модель реальной раскладки.

1. `product.json`: `price`, `cost`, `volume_liters` (габариты в мм: `высота × ширина × глубина / 1 000 000`), `drr` (доля),
   `commission_micro`, `commission_low`, `commission_high` (навык `category-commissions`; у магазина с ИУ — его ставки из
   `stores_commission_rules_list`); при желании другие входы формулы.
2. Сохранить ответы `stores_economics_settings_get` и `unit_economics_plan_list` магазина: медиана его строк даёт выкуп, отмены,
   последнюю милю, эквайринг, утилизацию, досрочную; кросс-докинг — объём × медиана «`supply_cost` ÷ `volume_liters`», без поставок —
   объём × 15 ₽ (`sources.supply_cost`: `store_per_liter` или `default_per_liter` — назвать). Логистику из медианы не брать.
3. Запустить:

```sh
python3 scripts/new_product_plan.py --inputs product.json --settings settings.json --plan plan.json
```

`--json` — входы с источниками, шаги, тарифы по кластерам, локальная база `ideal`, запас `margin` и итог `average` с запасом.
В ответе: объём и его диапазон, тарифы с 30.10.2026, источник долей, запас 25 п.п. и его рубли, средний тариф бакета цены,
ставка вознаграждения, прибыль с единицы, маржа, рентабельность; входы «по умолчанию» назвать. Если нет подходящих маршрутов,
логистика неизвестна, универсальным тарифом её не заменять.
