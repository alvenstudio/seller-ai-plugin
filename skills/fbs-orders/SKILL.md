# FBS: сборка, доп. информация, отмена, тариф отгрузки

Всё — инструментами MCP Seller AI. `store_id` — из `stores_list`. Чтение отправлений — как в навыке `orders`
(`postings_fbs_list`, `postings_fbs_get`). Скрипты (`scripts/`) только считают по уже полученным ответам и склеивают PDF;
в сеть не ходят.

**Пока недоступно в Seller AI** (делается в кабинете Ozon, агент так и говорит):
- отгрузки (акты, перевозки), грузоместа отгрузки и их этикетки, лист отгрузки;
- частичная сборка и частичная отмена товаров, страна производства, правка доп. информации после сборки, число коробок
  многокоробочного отправления.

## Перед любой командой

1. `stores_logistics_writes_get` (или `writes` в ответе `postings_fbs_list`): `writes.enabled = false` — команды сейчас
   не отправляются (`reason`: `not_configured` / `disabled`), сказать это и остановиться.
2. Показать пользователю, что изменится: какие отправления, сколько штук, что будет разделено и на сколько, что пропущено и
   почему. Сборка с разделением и отмена **необратимы** — для них нужно явное «да» пользователя.
3. Один `idempotency_key` на одно намерение (например `fbs-ship-<склад>-<дата>-<круг>`) или без него — MCP выведет ключ из
   аргументов. Тот же ключ при повторе вызова не отправит команду второй раз.
4. Ответ команды: `200` — итог есть, смотреть `operation.status`; `202` — ещё идёт: `operations_get` с `operation_id`, пока
   статус не станет конечным. Готово только при `succeeded`. `outcome_unknown` **никогда не повторять** — выяснять чтением
   (`postings_fbs_get` отправления, `operations_check`). `failed` — показать `message`; новая попытка — новая команда с новым
   ключом и только по слову пользователя.

## Сборка «одно отправление — одна штука»

### План (ничего не меняет)

1. `postings_fbs_list` с `tab=awaiting_packaging`, `warehouse_ids=<склад>` и `search=<артикул>` (или без `search` — «всё по
   складу»), все страницы по `next_cursor`. Склады магазина и их число отправлений — `filters.warehouses` того же ответа; как
   пользователь называет склады («Москва», «с Шагольской») — держать в своих настройках агента.
2. Отобрать отправления с нужным товаром: смешанные заказы (с другими товарами) собираются целиком, их чужие товары назвать
   отдельной строкой.
3. Разложить:
   - одна штука в отправлении — «Собрать все» одной упаковкой;
   - несколько штук — «Собрать» с разделением: по упаковке на каждую штуку;
   - `needs_additional_info = true` или в `actions` «Ввести доп. инфо» — сначала доп. информация (ниже), иначе Ozon не соберёт.
4. Показать план: склад, заказов → отправлений после разделения, штук по товарам, смешанных, сколько нужно доп. информации,
   диапазон `shipment_date` по МСК; склад не назван («собери компот») — собирать там, где есть заказы, и сказать, сколько их на
   других складах.

### Выполнение (после «да»)

- **Одна штука:** `postings_fbs_ship_all` с `body = {"posting_numbers": [...]}` — не больше 50 номеров за вызов, каждое
  отправление одной упаковкой. Ответ: `operations[]` (по операции на отправление) и `skipped[]` с кодом и текстом:
  `posting_not_awaiting_packaging` (уже собрано или отменено), `extra_info_required` (нужна доп. информация),
  `multibox_in_cabinet` (многокоробочное — только в кабинете), `not_found`, `target_busy` (по отправлению уже идёт команда).
- **Несколько штук:** `postings_fbs_ship` на каждое отправление, `posting` = номер,
  `body = {"packages": [{"products": [{"sku": "<sku>", "quantity": 1}]}, …], "confirm_split": true}` — упаковок столько,
  сколько штук; сумма по SKU должна совпасть с отправлением (иначе 422 `quantity_mismatch`). Без `confirm_split` — 409
  `split_confirmation_required`. Предупреждение пользователю: «Разделить заказ на N отправлений? Разделение нельзя отменить:
  у каждого отправления будет своя этикетка».
- 200 от Ozon — ещё не сборка: Seller AI подтверждает её чтением отправления, итог — статус операции. `failed` с
  `status_reason = not_applied` — «Ozon не смог собрать отправление» (`ship_failed`): предложить собрать ещё раз.
- Новые номера после разделения — в элементах операции; все отправления заказа — `postings_fbs_list` с
  `posting_number=<номер заказа>`, у выделенных `parent_posting_number` — исходное.

### Ловушки

- Ошибка Ozon при разделении может оставить часть: исходное собрано, соседние отправления заказа ещё `awaiting_packaging`.
  Прочитать все отправления заказа и предложить дособрать оставшиеся (каждое — по одной штуке).
- Отправление, собранное раньше без разделения (в кабинете, другим сервисом), Ozon уже не делит: одна этикетка на все штуки.
  Назвать номер и состав («пастила 1000 ×5 в одной упаковке») — штуки упаковываются вместе.
- «Отправление уже собрано», «Не заполнена доп. информация», «Габариты или вес выше ограничений пункта приёма» — тексты Ozon
  в `message` операции; назвать номера, остальную сборку не задерживать.
- Тариф отгрузки и просрочку решает момент **передачи**, а не сборка: после «Собрать» ничего не обещать о скидке.

### Отчёт

Сколько заказов → сколько отправлений; собрано (`succeeded`), не собрано и почему (`skipped`, `failed`), выбывшие
(отменённые) номера; диапазон отгрузки по МСК; что осталось на других складах. Этикетки — `postings_fbs_labels_download` (`posting_numbers` через запятую, до 20 за вызов; файл PDF в ответе),
через 45–60 секунд после сборки, как советует Ozon; больше 20 — несколькими вызовами.

## Доп. информация: маркировка, ГТД, РНПТ, вес

1. `postings_fbs_exemplars_get` (`posting`) — экземпляры и что нужно: у товара `quantity`, `needs` (`mandatory_mark`, `gtd`,
   `rnpt`, `jw_uin`, `weight`), `weight_range`, `exemplars[]` с `exemplar_id` (Ozon выдаёт их один раз и потом те же).
2. Собрать у пользователя данные: коды «Честного ЗНАКа» по экземплярам, ГТД (или «ГТД нет» — `gtd_absent: true`), РНПТ.
3. `postings_fbs_exemplars_validate` с тем же телом, что пойдёт в сохранение: `valid` и ошибки по экземплярам — показать.
4. После «да» — `postings_fbs_exemplars_set`: **полный** набор всех товаров отправления
   (`{"products": [{"sku": "…", "exemplars": [{"exemplar_id": "…", "marks": [{"mark": "…", "mark_type": "mandatory_mark"}],
   "gtd": null, "gtd_absent": true, "rnpt": null, "rnpt_absent": false, "weight": null}]}]}`), ровно `quantity` экземпляров у
   каждого. Операция ждёт проверки Ozon: `succeeded` — «доп. информация принята, можно собирать»; `failed` — ошибки по знакам
   (например «Для страны производства товара нужна ГТД»).
5. Затем — сборка, как выше.

## Отмена отправления

1. `postings_fbs_cancel_reasons_list` (`posting`) — причины сейчас (`source: live`; `mirror` — Ozon не ответил, взяты последние
   известные): `id`, `title`, `seller_fault`, `message_required`.
2. Показать причины. Причина по вине продавца (`seller_fault`: «товар закончился», «остался только брак», «другое (вина
   продавца)»…) — предупредить: «отмена войдёт в индекс ошибок FBS и может повлечь плату за обработку».
3. Явное «да» на конкретный номер и причину: «Отменить отправление N? Отмена необратима».
4. `postings_fbs_cancel`: `body = {"cancel_reason_id": "<id>", "cancel_reason_message": null, "confirm": true}`; для причины с
   `message_required` — текст 1–500 символов. 409 `posting_not_cancellable` — уже отменено или доставлено.
5. Готово, когда операция `succeeded` (отправление прочитано `cancelled`).

## Тариф отгрузки: что сдать в ближайшее окно

У каждого отправления в `postings_fbs_list` есть `tariff`: `current`, `next` и шкала `steps[]` — `effect` (`discount` —
«Скидка», `none` — «Без скидки», `penalty` — «Штраф»), `rate` (%), `charge` (₽), `deadline_at` (до когда держится ступень).
Ступени Ozon задаёт сам; ставки не придумывать.

1. Взять у пользователя **реальные окна сдачи** по МСК («через час», «завтра в 11–12 по Екатеринбургу» → перевести в МСК).
2. `postings_fbs_list` `tab=awaiting_packaging` и `tab=awaiting_deliver` склада, все страницы — сохранить ответы в файл.
3. План: `python3 scripts/fbs_bonus.py postings.json --ship-at "2026-10-19 19:00" --next-ship-at "2026-10-20 11:30"
   --warehouse <warehouse.id>` — по товару и состоянию: ₽ в ближайшее окно, в следующее, потеря при переносе; отправления без
   шкалы — отдельно как «неизвестно» (не ноль).
4. Порядок: уже собранное и наклеенное — первым; что к следующему окну выйдет на «Без скидки» или «Штраф» — сейчас; что и к
   следующему окну сохранит ступень — можно отложить; уже на штрафе — немедленно.
5. Отбор N штук: `… --offer "<артикул>" --need N --out pick.json` — наибольшая потеря на штуку, при равенстве от старых к
   новым, только чистые заказы товара (`--allow-mixed` — и смешанные); `--exclude` — номера, уже распределённые. Номера из
   `pick.json` — в сборку выше. «N шт» и «N заказов» — разное: брать слово пользователя.
6. «Срочные, пока не сгорела скидка»: отправления, у которых срок текущей ступени-скидки (`deadline_at`) позже окна сдачи, от
   старых к новым.

## Сколько отгружено по FBS

`orders_list` с `scheme=fbs`, `offer_id` (или `sku`), `date_from`/`date_to` (по дате создания, МСК), постранично
(`limit` ≤ 500, `offset`). Группировать по `warehouse_name` и статусу: «отгружено» — всё, что передано в доставку
(`sent_by_seller`, `driver_pickup`, `delivering`, `delivered`); собрано и ждёт — `awaiting_deliver`; не собрано —
`awaiting_packaging`, `awaiting_registration`, `acceptance_in_progress`, `awaiting_approve`; спорные — `arbitration`,
`client_arbitration`, `not_accepted`; отменено — `cancelled`. По дням отгрузки — по `shipment_date` (МСК). Штуки — сумма
`products[].quantity` нужного товара; число отправлений без товаров — `total` при `limit=1` с фильтром `status`.
Уточнения («а из Москвы?») — из уже посчитанного.

После сдачи: отправления, которые через день после своей даты отгрузки всё ещё `awaiting_deliver`, хаб, скорее всего, не
принял (коробки нет или её не отсканировали) — назвать списком (номер, товар, дата отгрузки), пока не истёк срок.

## Двойная этикетка (товарная + FBS на одном листе)

FBS-этикетки — `postings_fbs_labels_download` (PDF в ответе, сохранить файлом); товарную делает навык `product-label`
(или пользователь присылает свою).

```bash
python3 scripts/combine_labels.py <товарная.pdf> <fbs.pdf> <out.pdf> --size 75x120 [--limit 1]
# 58x80 — половины 1:1, без поля: --size 58x80 --margin 0
```

Сначала одна страница (`--limit 1`), рендер `pdftoppm -png -r 200` и пробная печать с проверкой сканером QR/штрихкода;
весь файл — после «да». Одна товарная страница кладётся на все FBS-страницы: другой товар в FBS-файле = ошибка, сверять
с артикулом. Имя файла — понятное: «Курага 400 двойные 90.pdf».

## Перевыпуск этикетки по фото

Номер на фото часто перевёрнут или обрезан. Кандидаты — `postings_fbs_list` `tab=awaiting_deliver` (и `search` по товару,
если он известен), совпадение по фрагментам цифр локально; номер бывает 8- и 10-значным, искать известные номера
подстрокой. Назвать найденный номер и по чему опознан; файл этикетки — `postings_fbs_labels_download` с этим номером (старая этикетка остаётся действительной).
