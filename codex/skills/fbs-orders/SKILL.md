# FBS: сборка, доп. информация, отмена, отгрузки, тариф отгрузки

Всё — инструментами MCP Seller AI. `store_id` — из `stores_list`. Чтение отправлений — как в навыке `orders`
(`postings_fbs_list`, `postings_fbs_get`). Скрипты (`scripts/`) только считают по уже полученным ответам и склеивают PDF;
в сеть не ходят.

**Пока недоступно в Seller AI** (делается в кабинете Ozon, агент так и говорит): раскладка отправлений по грузоместам
доверительной приёмки и документы грузомест, акт о расхождениях, пропуска на склад, споры по отправлениям. Нужное пользователю — запросом функции, сам, без его просьбы (навык `feedback`).

## Перед любой командой

1. `stores_logistics_writes_get` (или `writes` в ответе `postings_fbs_list`): `writes.enabled = false` — команды сейчас
   не отправляются (`reason`: `not_configured` / `disabled`), сказать это и остановиться.
2. **Согласие.** Полная просьба — согласие: «собери все FBS со склада Москва», «собери пастилу 1000 по одной штуке»,
   «введи эти коды маркировки в 12345678-0001-1» — выполнить и показать итог: какие отправления, сколько штук, что
   разделено и на сколько, что пропущено и почему. Один вопрос — когда чего-то не хватает или неоднозначно: склад не
   назван, а заказы на нескольких складах; в просьбе нет «по одной штуке», а в отправлениях по несколько штук (делить
   или нет: разделение не отменить, у каждой части своя этикетка); план расходится с просьбой. Делить — только когда
   пользователь это назвал («по одной штуке», «раздели», «собери без …»). **Необратимые** — отмена отправления
   (`postings_fbs_cancel`), отмена части товаров (`postings_fbs_products_cancel`) и удаление отгрузки
   (`postings_fbs_carriages_cancel`): всегда показать, что будет (номер, товары и причину; у отгрузки — метод, день и
   число отправлений), и ждать явного «да».
3. Один `idempotency_key` на одно намерение (например `fbs-ship-<склад>-<дата>-<круг>`) или без него — MCP выведет ключ из
   аргументов. Тот же ключ при повторе вызова не отправит команду второй раз.
4. Ответ команды: `200` — итог есть, смотреть `operation.status`; `202` — ещё идёт: `operations_get` с `operation_id`, пока
   статус не станет конечным. Готово только при `succeeded`. `outcome_unknown` **никогда не повторять** — выяснять чтением
   (`postings_fbs_get` отправления, `operations_check`). `failed` — показать `message`; новая попытка — новая команда с новым
   ключом и только по слову пользователя.

## Сборка «одно отправление — одна штука»

### План (ничего не меняет)

1. `postings_fbs_list` с `tab=awaiting_packaging`, `warehouse_ids=<склад>` и `search=<артикул>` (или без `search` — «всё по
   складу»), все страницы по `next_cursor`. Склады магазина и их число отправлений — `filters.warehouses` того же ответа; как
   пользователь называет склады («Москва», «с Шагольской») — держать в своих настройках агента.
2. Отобрать отправления с нужным товаром: смешанные заказы (с другими товарами) собираются целиком, их чужие товары назвать
   отдельной строкой.
3. Разложить:
   - одна штука в отправлении — «Собрать все» одной упаковкой;
   - несколько штук — «Собрать» с разделением: по упаковке на каждую штуку;
   - `needs_additional_info = true` или в `actions` «Ввести доп. инфо» — сначала доп. информация (ниже), иначе Ozon не соберёт.
4. План: склад, заказов → отправлений после разделения, штук по товарам, смешанных, сколько нужно доп. информации,
   диапазон `shipment_date` по МСК. Склад не назван («собери компот»), а заказы только на одном — собирать там; на
   нескольких — спросить один раз (раздел «Согласие»). План по полной просьбе — не вопрос, а первая часть отчёта.

### Выполнение

- **Одна штука:** `postings_fbs_ship_all` с `body = {"posting_numbers": [...]}` — не больше 50 номеров за вызов, каждое
  отправление одной упаковкой. Ответ: `operations[]` (по операции на отправление) и `skipped[]` с кодом и текстом:
  `posting_not_awaiting_packaging` (уже собрано или отменено), `extra_info_required` (нужна доп. информация),
  `multibox_in_cabinet` (многокоробочное без числа коробок — сначала оно, раздел «Многокоробочное отправление»), `not_found`,
  `target_busy` (по отправлению уже идёт команда).
- **Несколько штук:** `postings_fbs_ship` на каждое отправление, `posting` = номер,
  `body = {"packages": [{"products": [{"sku": "<sku>", "quantity": 1}]}, …], "confirm_split": true}` — упаковок столько,
  сколько штук; сумма по SKU должна совпасть с отправлением (иначе 422 `quantity_mismatch`). Без `confirm_split` — 409
  `split_confirmation_required`. `confirm_split: true` — только когда разделение названо в просьбе; иначе один вопрос:
  «Разделить заказ на N отправлений? Разделение нельзя отменить: у каждого отправления будет своя этикетка».
- 200 от Ozon — ещё не сборка: Seller AI подтверждает её чтением отправления, итог — статус операции. `failed` с
  `status_reason = not_applied` — «Ozon не смог собрать отправление» (`ship_failed`): предложить собрать ещё раз.
- Новые номера после разделения — в элементах операции; все отправления заказа — `postings_fbs_list` с
  `posting_number=<номер заказа>`, у выделенных `parent_posting_number` — исходное.

### Ловушки

- Ошибка Ozon при разделении может оставить часть: исходное собрано, соседние отправления заказа ещё `awaiting_packaging`.
  Прочитать все отправления заказа и предложить дособрать оставшиеся (каждое — по одной штуке).
- Отправление, собранное раньше без разделения (в кабинете, другим сервисом), Ozon уже не делит: одна этикетка на все штуки.
  Назвать номер и состав («пастила 1000 ×5 в одной упаковке») — штуки упаковываются вместе.
- «Отправление уже собрано», «Не заполнена доп. информация», «Габариты или вес выше ограничений пункта приёма» — тексты Ozon
  в `message` операции; назвать номера, остальную сборку не задерживать.
- Тариф отгрузки и просрочку решает момент **передачи**, а не сборка: после «Собрать» ничего не обещать о скидке.

### Отчёт

Сколько заказов → сколько отправлений; собрано (`succeeded`), не собрано и почему (`skipped`, `failed`), выбывшие
(отменённые) номера; диапазон отгрузки по МСК; что осталось на других складах; этикетки — «проверено N из N» (ниже).

## Частичная сборка: собрать часть отправления

Когда отправить можно не всё («одного товара нет — собери остальное»): `postings_fbs_ship_package` (`posting`),
`body = {"products": [{"sku": "<sku>", "quantity": N}], "confirm_split": true}` — названные штуки Ozon собирает в
отдельное отправление, остальное ждёт сборки. Это разделение, его не отменить: `confirm_split: true` — только когда
пользователь сам сказал собрать часть; иначе один вопрос («Собрать N шт. отдельным отправлением? Остальное останется ждать
сборки, разделение нельзя отменить»). Без `confirm_split` — 409 `split_confirmation_required`.
- Все штуки сразу — не сюда, а `postings_fbs_ship` (422 `whole_posting`); SKU не из отправления — `sku_not_in_posting`,
  больше, чем в отправлении, — `exceeds_posting`.
- Товар с доп. информацией — сначала она (ниже), и у товара `exemplar_ids` — по одному `exemplar_id` на штуку
  (`postings_fbs_exemplars_get`).
- Итог — статус операции; номера отправлений после разделения — заметка `postings_formed` и `postings_fbs_list` с
  `posting_number=<номер заказа>`. `ship_failed` — как у сборки: собрать ещё раз новой командой.

## Многокоробочное отправление

`multibox_in_cabinet` у сборки — в отправлении многокоробочный товар, и Ozon ждёт число коробок до сборки. Число — от
пользователя (не названо — спросить), затем `postings_fbs_multibox_qty_set` (`posting`, `body = {"multi_box_qty": N}`,
1–1000) и после `succeeded` — сборка как обычно. 409 `not_multibox` — многокоробочного товара в отправлении нет;
`posting_not_awaiting_packaging` — уже собрано. Ozon отказал (`failed`, текст в `message`) — назвать и предложить кабинет.

## Этикетки FBS: скачать, проверить, разложить

**Главное правило: файлы этикеток отдаются пользователю только после проверки каждой страницы.** Ошибка в рулоне —
чужой товар в коробке, дубль или пропущенная отменённая этикетка — дороже минуты на проверку.

1. **Скачать** — `postings_fbs_labels_download` (`posting_numbers` через запятую, до 20 за вызов; PDF в ответе —
   сохранить файлом), через 45–60 секунд после сборки, как советует Ozon; больше 20 — несколькими вызовами, по порядку.
   - 409 `labels_not_ready` (`retry_after`) — Ozon ещё делает этикетки (45–60 с после сборки): подождать `retry_after` и
     вызвать снова с теми же номерами.
   - 422 `validation` с кодом `not_awaiting_deliver` (`items [{posting_number, status}]`) — одно неподходящее
     отправление (отменено, ещё не собрано, уже передано) валит весь вызов: убрать эти номера, назвать их со статусом
     (отменённые — «этикетку не клеить, коробку разобрать») и скачать остальные.
2. **Проверить** — перечитать `postings_fbs_list` (`tab=awaiting_deliver`, все страницы) прямо перед проверкой, затем
   ```bash
   python3 scripts/verify_labels.py --postings postings.json --pdf labels-1.pdf --pdf labels-2.pdf        --expected shipped.json --offer "<артикул>" --warehouse <warehouse.id> [--multi-ok multi.json] --now "<сейчас, UTC>"
   ```
   `shipped.json` — номера, собранные в этом круге (из операций сборки). Каждая страница — ровно один ожидаемый номер,
   без дублей и пропусков, статус «ожидает отгрузки», нужный склад, 1 шт нужного товара (собранные раньше без деления —
   в `--multi-ok`). Арифметика: этикеток = собранных отправлений − выбывших (отменённых). Код выхода 1 — файлы не
   отдавать: исправить (перескачать без лишних, добавить пропущенные) и проверить снова. В отчёте — «проверено N из N».
3. **Разложить по файлам** (лимит страниц на рулон, отдельный файл на товар, перепечатка первой, двойные этикетки):
   ```bash
   python3 scripts/labels_pack.py --postings postings.json --pdf labels-1.pdf --pdf labels-2.pdf --out-dir labels        [--per-file 100] [--first reprint.json] [--product-label "<артикул>=товарная.pdf" --size 75x120]
   ```
   Отдельный файл на товар («<артикул> N шт.pdf»), собранные раньше без деления — отдельно по составу упаковки («… по 3
   шт в упаковке»), смешанные заказы — отдельно (их чужие товары назвать); больше лимита — «(часть K из M)». Лимит и
   шаблон — из последней фразы пользователя. Готовые файлы ещё раз прогнать `verify_labels.py`.

**Перепечатка уже собранных** («перепечатай пастилу», «этикетки потерялись»): `postings_fbs_list` с `tab=awaiting_deliver`
и `search=<артикул>` (склад — `warehouse_ids`), все страницы → `postings_fbs_labels_download` по 20 → проверка (шаг 2) →
`labels_pack.py` с `--first` (перепечатка — в начало рулона, если её печатают вместе с новыми). Собранные раньше без
деления — отдельный файл на каждый состав упаковки. Старая этикетка при перепечатке остаётся действительной.

## Доп. информация: маркировка, ГТД, РНПТ, вес

1. `postings_fbs_exemplars_get` (`posting`) — экземпляры и что нужно: у товара `quantity`, `needs` (`mandatory_mark`, `gtd`,
   `rnpt`, `jw_uin`, `weight`), `weight_range`, `exemplars[]` с `exemplar_id` (Ozon выдаёт их один раз и потом те же).
2. Собрать у пользователя данные: коды «Честного ЗНАКа» по экземплярам, ГТД (или «ГТД нет» — `gtd_absent: true`), РНПТ.
   Чего не хватает (кодов меньше, чем экземпляров; про ГТД не сказано) — спросить одним сообщением.
3. `postings_fbs_exemplars_validate` с тем же телом, что пойдёт в сохранение: `valid` и ошибки по экземплярам — показать.
4. Данные полные и проверка прошла — `postings_fbs_exemplars_set`: **полный** набор всех товаров отправления
   (`{"products": [{"sku": "…", "exemplars": [{"exemplar_id": "…", "marks": [{"mark": "…", "mark_type": "mandatory_mark"}],
   "gtd": null, "gtd_absent": true, "rnpt": null, "rnpt_absent": false, "weight": null}]}]}`), ровно `quantity` экземпляров у
   каждого. Операция ждёт проверки Ozon: `succeeded` — «доп. информация принята, можно собирать»; `failed` — ошибки по знакам
   (например «Для страны производства товара нужна ГТД»).
5. Затем — сборка, как выше.

**Страна-изготовитель.** У товара в `postings_fbs_get` в `requirements` есть `country` (или `change_country`) — Ozon
просит страну до сборки. Код страны — `postings_fbs_countries_list` (`search` — название, «Китай»), затем
`postings_fbs_products_country_set` (`posting`, `sku`, `body = {"country_iso_code": "CN"}`); готово при `succeeded` (Ozon
больше не просит страну). Потом перечитать `postings_fbs_get`: появилась `gtd` — нужна ГТД, ввести её доп. информацией
(шаги выше). 409 `country_not_required` — Ozon страну у этого товара не просит.

**Правка после сборки** (в `actions` отправления есть `update_additional_info` — «Изменить доп. инфо»; отправление ждёт
отгрузки): `postings_fbs_exemplars_get` → новые данные `postings_fbs_exemplars_set` (полный набор, как выше; проверка
Ozon кончается «можно сохранить правку», операция `succeeded`) → `postings_fbs_exemplars_update` (`posting`, `body = {}`)
сохраняет правку. 409 `exemplars_not_checked` — последняя проверка Ozon не разрешила правку: сначала `exemplars_set`.

## Отмена отправления

1. `postings_fbs_cancel_reasons_list` (`posting`) — причины сейчас (`source: live`; `mirror` — Ozon не ответил, взяты последние
   известные): `id`, `title`, `seller_fault`, `message_required`.
2. Показать причины. Причина по вине продавца (`seller_fault`: «товар закончился», «остался только брак», «другое (вина
   продавца)»…) — предупредить: «отмена войдёт в индекс ошибок FBS и может повлечь плату за обработку».
3. Явное «да» на конкретный номер и причину: «Отменить отправление N? Отмена необратима». Просьба «отмени N» с причиной
   этого «да» не заменяет: отмена — необратимая команда.
4. `postings_fbs_cancel`: `body = {"cancel_reason_id": "<id>", "cancel_reason_message": null, "confirm": true}`; для причины с
   `message_required` — текст 1–500 символов. 409 `posting_not_cancellable` — уже отменено или доставлено.
5. Готово, когда операция `succeeded` (отправление прочитано `cancelled`).

## Отмена части товаров

Когда часть товаров отправления не будет отправлена, а остальное — будет: `postings_fbs_products_cancel` (`posting`),
`body = {"cancel_reason_id": "<id>", "cancel_reason_message": "<текст>", "items": [{"sku": "<sku>", "quantity": N}],
"confirm": true}`. Причины — `postings_fbs_cancel_reasons_list` того же отправления (422 `reason_not_available` — причины
нет в списке); текст Ozon требует всегда (`message_required`). Все штуки — это отмена отправления (выше; 422
`whole_posting`). Необратимо: показать номер, товары, количество и причину (по вине продавца — предупредить про индекс
ошибок FBS) и ждать «да». 409 `posting_not_cancellable` — отправление уже отменено или доставлено. Готово при
`succeeded` (в отправлении прочитано на столько штук меньше).

## Отгрузки: создать, состав, подтвердить, лист отгрузки

Отгрузка — то, что сдаётся одному методу доставки в один день, с листом отгрузки (акт и транспортная накладная).

1. **День** — `postings_fbs_carriages_list` (`departure_date` — ГГГГ-ММ-ДД по МСК, по умолчанию сегодня):
   `delivery_methods[]` — методы дня (`postings.to_pack` — ещё собрать, `postings.packed` — собрано, `cutoff_at` — собрать
   до, `timeslot`), их отгрузки `carriage_ids` и `can_create` (Ozon даёт создать отгрузку); `carriages[]` — отгрузки дня
   (`status`: `new` — создана, состав ещё меняется; дальше — подтверждена, передана, закрыта, `cancelled`; `postings_count`,
   `documents_status`, `cancel_available`). `warnings` (синхронизация отстаёт, не удалось перечитать) — сказать.
2. **Создать** — `postings_fbs_carriages_create`, `body = {"delivery_method_id": "<id>", "departure_date": "<день>"}`: Ozon
   кладёт в неё все собранные отправления метода. Номер новой отгрузки — `carriage_id` операции. 409
   `carriage_not_creatable` — Ozon сейчас не даёт создать (`carriage_ids` — уже созданные отгрузки дня: работать с ними);
   404 — у метода нет отправлений к отгрузке в этот день. Неизвестный исход не повторять: операция сама ищет отгрузку у
   Ozon; заметка `carriages_found` — нашлось несколько новых: проверить их и не создавать снова.
3. **Состав** — `postings_fbs_carriages_get` (`carriage`): `postings[]` с товарами. Сверить с собранными отправлениями метода
   (`postings_fbs_list`, `tab=awaiting_deliver`, `delivery_method_ids`). Изменить — `postings_fbs_carriages_postings_set`,
   `body = {"posting_numbers": [...]}` — **весь** список (Ozon заменяет состав), только у отгрузки `new`; каждое
   отправление должно ждать отгрузки (422 `not_awaiting_deliver` с номерами и статусами).
4. **Подтвердить** — `postings_fbs_carriages_approve` (`body = {}`; `containers_count` — только при доверительной
   приёмке): после него Ozon делает документы и штрихкод отгрузки (`barcode` у отгрузки). Только у `new` (иначе 409
   `carriage_not_approvable`).
5. **Документы** — `postings_fbs_carriages_documents_download` (лист отгрузки с транспортной накладной) и
   `postings_fbs_carriages_container_labels_download` (этикетки грузомест), PDF в ответе — сохранить файлом. 409
   `documents_not_ready` / `labels_not_ready` — Ozon ещё делает: подождать `retry_after` и вызвать снова.
6. **Удалить** — `postings_fbs_carriages_cancel`, `body = {"confirm": true}`: необратимо, её отправления ждут следующей
   отгрузки (`warnings` `cancel_carriage` — сколько). Показать номер, метод, день, число отправлений и ждать «да». 409
   `carriage_not_cancellable` — уже удалена или Ozon не даёт (`reason`); отказ Ozon в ответе — `failed` с его текстом.

Полная просьба («сформируй отгрузку на сегодня по методу …») — создать, сверить состав, подтвердить и отдать лист
отгрузки; отчёт — номер отгрузки, сколько отправлений, что не вошло и почему.

## Тариф отгрузки: что сдать в ближайшее окно

У каждого отправления в `postings_fbs_list` есть `tariff`: `current`, `next` и шкала `steps[]` — `effect` (`discount` —
«Скидка», `none` — «Без скидки», `penalty` — «Штраф»), `rate` (%), `charge` (₽), `deadline_at` (до когда держится ступень).
Ступени Ozon задаёт сам; ставки не придумывать.

1. Взять у пользователя **реальные окна сдачи** по МСК («через час», «завтра в 11–12 по Екатеринбургу» → перевести в МСК).
2. `postings_fbs_list` `tab=awaiting_packaging` и `tab=awaiting_deliver` склада, все страницы — сохранить ответы в файл.
3. План: `python3 scripts/fbs_bonus.py postings.json --ship-at "2026-10-19 19:00" --next-ship-at "2026-10-20 11:30"
   --warehouse <warehouse.id>` — по товару и состоянию: ₽ в ближайшее окно, в следующее, потеря при переносе; отправления без
   шкалы — отдельно как «неизвестно» (не ноль).
4. Порядок: уже собранное и наклеенное — первым; что к следующему окну выйдет на «Без скидки» или «Штраф» — сейчас; что и к
   следующему окну сохранит ступень — можно отложить; уже на штрафе — немедленно.
5. Отбор N штук: `… --offer "<артикул>" --need N --out pick.json` — наибольшая потеря на штуку, при равенстве от старых к
   новым, только чистые заказы товара (`--allow-mixed` — и смешанные); `--exclude` — номера, уже распределённые. Номера из
   `pick.json` — в сборку выше. «N шт» и «N заказов» — разное: брать слово пользователя.
6. «Срочные, пока не сгорела скидка»: отправления, у которых срок текущей ступени-скидки (`deadline_at`) позже окна сдачи, от
   старых к новым.

## Сколько отгружено по FBS

`orders_list` с `scheme=fbs`, `offer_id` (или `sku`), `date_from`/`date_to` (по дате создания, МСК), постранично
(`limit` ≤ 500, `offset`). Группировать по `warehouse_name` и статусу: «отгружено» — всё, что передано в доставку
(`sent_by_seller`, `driver_pickup`, `delivering`, `delivered`); собрано и ждёт — `awaiting_deliver`; не собрано —
`awaiting_packaging`, `awaiting_registration`, `acceptance_in_progress`, `awaiting_approve`; спорные — `arbitration`,
`client_arbitration`, `not_accepted`; отменено — `cancelled`. По дням отгрузки — по `shipment_date` (МСК). Штуки — сумма
`products[].quantity` нужного товара; число отправлений без товаров — `total` при `limit=1` с фильтром `status`.
Уточнения («а из Москвы?») — из уже посчитанного.

После сдачи: отправления, которые через день после своей даты отгрузки всё ещё `awaiting_deliver`, хаб, скорее всего, не
принял (коробки нет или её не отсканировали) — назвать списком (номер, товар, дата отгрузки), пока не истёк срок.

## Двойная этикетка (товарная + FBS на одном листе)

FBS-этикетки — `postings_fbs_labels_download` (PDF в ответе, сохранить файлом); товарную делает навык `product-label`
(или пользователь присылает свою).

```bash
python3 scripts/combine_labels.py <товарная.pdf> <fbs.pdf> <out.pdf> --size 75x120 [--limit 1]
# 58x80 — половины 1:1, без поля: --size 58x80 --margin 0
```

Сначала одна страница (`--limit 1`), рендер `pdftoppm -png -r 200` и пробная печать с проверкой сканером QR/штрихкода;
весь файл — после «да». Одна товарная страница кладётся на все FBS-страницы: другой товар в FBS-файле = ошибка, сверять
с артикулом (FBS-файл сначала — `verify_labels.py --offer`). Имя файла — понятное: «Курага 400 двойные 90.pdf». Много
FBS-файлов и несколько товаров сразу — `labels_pack.py --product-label "<артикул>=<товарная.pdf>"`: двойные этикетки
по товару, остальные — как есть.

## Перевыпуск этикетки по фото

Номер на фото часто перевёрнут или обрезан. Кандидаты — `postings_fbs_list` `tab=awaiting_deliver` (и `search` по товару,
если он известен), совпадение по фрагментам цифр локально; номер бывает 8- и 10-значным, искать известные номера
подстрокой. Сверять и штрихкоды этикетки — `barcodes.upper` / `barcodes.lower` строки отправления, — и город назначения:
скачать этикетку кандидата (`postings_fbs_labels_download`) и сравнить её текст (первая строка — город, потом номер
блоками) с фото. Назвать найденный номер и по чему опознан; отдать файл этой этикетки (старая остаётся действительной).
