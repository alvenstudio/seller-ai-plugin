# Комплекты из готовых Super-заявок

Вход: магазин, точный SKU и фасовка, целое количество. Название сопоставить с SKU однозначно (`products_list` с
`search`), похожую фасовку не подставлять. Заявки здесь **не создаются и состав не меняется** — только выбор целых
поставок, таймслот и этикетки. Новые заявки — навык `supplies-create` или `supplies-super`. Пользователь передумал брать
из поданных («с нуля», «всё новой заявкой») — навык `supplies-create`, шаг 3а, «Полностью с нуля».

## Правила отбора

- **Атом — целая поставка** (кластер) заявки: весь её товар, все места и этикетки. Можно взять часть поставок
  многокластерной заявки. Поставку со смешанными SKU не брать — её не разделить.
- **Пригодна поставка `READY_TO_SUPPLY` или `DATA_FILLING`** — по статусу самой поставки, не заявки, с таймслотом
  заявки или без (владелец, 06.11.2026). Чего у заявки не хватает — слота (`needs_timeslot`), водителя и машины
  (`needs_vehicle`) — заполняет шаг 6, и поставка взята. У частично отгруженной заявки (`IN_TRANSIT`,
  `ACCEPTANCE_AT_STORAGE_WAREHOUSE`, `REPORTS_CONFIRMATION_AWAITING`) готовые поставки тоже пригодны и считаются.
- **Товар сейчас в статусе Super** (`products_list` → `is_super: true`) — готовые Super-поставки не искать: подать новую
  заявку навыком `supplies-create` (владелец, 06.11.2026).
- Заявка — с меткой Super (`order.tags.super = true`; подключение продавца к Super её не заменяет), с грузоместами,
  состав каждого прочитан и в сумме равен количеству поставки. Текущий Super карточки — отдельный признак: без него
  старая Super-заявка всё равно пригодна.
- Только заявки той точки отгрузки (или того же города), откуда везут: `dropoff_ids` в `rows`. Точку не сверили — так и
  сказать.
- **Точное количество обязательно.** Ближайшее — только с решения пользователя. Повторы кластеров разрешены; запретил
  пользователь — `allow_repeats: false`.
- Приоритеты точного объёма (`select`, их держит скрипт): точная сумма → больше начатых заявок взято до конца → больше
  штук из начатых → больше разных кластеров → меньше новых заявок → меньше поставок → более ранний слот. Начатая заявка
  — часть её поставок уже отгружена или взята в комплекты (`exclude_supply_ids`), часть ещё ждёт.
- **По потребности — сначала покрытие** (владелец, 08.11.2026: «Лучше будет если суперами покроем потребность, чем
  новые заявки подавать. Новые заявки хуже того если мы не будем брать сгорающие поставки»): больше потребности закрыть
  готовыми поставками (с общим объёмом — ровно его), затем больше штук начатых заявок (их слот не перенести, невзятые
  сгорят), затем меньше заявок и слотов, меньше перебора, раньше слот. Держит скрипт.
- Метка Super — не цена: прогноза стоимости доставки нет ни в Seller AI, ни в API Ozon. Просят «бесплатные» —
  бесплатность каждой заявки и её слота пользователь сверяет в кабинете Ozon; в ответе назвать, что и когда сверено.
  Сверка годна сутки и только для того же слота и состава; 0 ₽ в кабинете — не гарантия, что других начислений не
  будет. Без сверки комплект бесплатным не называть: неизвестная стоимость — не ноль.

## Порядок

«Сколько готово к отгрузке» — только шаг 1 и итог: поставки, штуки, коробки по фасовке и заявки, в которых они лежат
(любого статуса заявки), без подбора, слотов и этикеток.

1. **Кандидаты.** `supplies_items_list` с `sku`, `super=true`, `supply_states=READY_TO_SUPPLY,DATA_FILLING`,
   `group_by=supply`, все страницы по `offset`: строки в `supplies` (заявка, поставка, кластер, точка отгрузки, слот,
   штуки). Фильтр `states` (статус заявки) не брать: начатые заявки выпадут, а подбор берёт их первыми. По каждой
   заявке — `supplies_orders_get` (по всем её поставкам видно, начата ли она). Затем
   ```bash
   python3 scripts/kits_select.py rows in.json   # {"sku", "orders": [ответы supplies_orders_get], "now": "<сейчас, UTC>", "dropoff_ids": [точки, откуда везут]}
   ```
   → `rows` (поставка, заявка, кластер, штуки, `units_per_place`, `started`, таймслот, точка) и `rejected` с причинами.
   `composition_complete: false` или `sync_pending` — состав не прочитан: так и сказать.
2. **Уже взятое** — только из этого разговора, без вопросов: поставки, взятые здесь в комплекты, и названные
   пользователем взятыми — в `exclude_supply_ids`. Истории нет — ничего не исключать: свободна каждая поставка-кандидат
   (выше, «Правила отбора»). Взятое нигде не записывать (файлы, заметки, память) и не просить пользователя вести список.
3. **Подбор.**
   ```bash
   python3 scripts/kits_select.py select in.json   # {"rows", "target", "allow_repeats", "exclude_supply_ids"}
   ```
   → выбранные поставки, сколько из начатых заявок и сколько добрано, кластеры и повторы, `started_leftovers_not_taken`.
   `proven: false` — оптимальность не доказана: сказать и предложить сузить кандидатов. Точной комбинации нет — назвать
   ближайшие достижимые суммы и спросить. Несколько объёмов («6000 и 3000») — `"targets": [6000, 3000]` вместо
   `target`: непересекающиеся комплекты по порядку пользователя, не вышло — в другом (`order_used`); подобрать все до
   слота первого.

   **По потребности** («возьми из поданных по потребности»): потребность по кластерам — `supplies_planning_availability`
   (`recommended_supply`) или план навыка `supplies-create`; `ads` — продажи в день из `supplies_planning_availability`
   (не виртуальный ADS плана), затем
   ```bash
   python3 scripts/kits_select.py by_need in.json   # {"rows", "need": [{"cluster_id", "name", "need", "ads"}], "exclude_supply_ids", "total"}
   ```
   → на нуждающийся кластер одна целая поставка, подбор — по правилу «По потребности» выше: `orders` и `slots` —
   заявки и слоты подбора, перебор — `over_days`, `from_started_orders` — штук из начатых, `started_leftovers_not_taken`
   — невзятые поставки начатых заявок (их слот не перенести — назвать пользователю номера и слот). `proven: false` —
   перебор оборван: покрытие и штуки начатых всё равно лучшие, а заявок, возможно, бывает меньше — так и сказать.
   Пользователь назвал общий объём («ровно 1128 шт») — передать `"total"`: взятое не больше него (`exact` — ровно), а
   `left_for_new_order` — ровно объём минус взятое; кластеры, чьи поставки не вошли, — `over_total`. Остаток новая
   заявка навыка `supplies-create` везёт по `new_order` — только в кластеры с продажами (`ads` > 0); непокрытое там, где
   продаж нет (`no_sales`), новой заявке не отдавать; остаток есть, а `new_order` пуст — спросить. Без `ads` продажи не
   проверены (`sales_checked: false`) — сказать. Итог: взятое + новая заявка = объём пользователя.
   Показать по городам «берём N шт (K кор.) при потребности M» и вариант «этот город не брать, подать новой заявкой».
4. **Показать подбор**: точная сумма; по городам — штуки, коробки (`units_per_place`), заявка ссылкой; сколько из начатых
   и сколько добрано; свободный остаток каждой взятой заявки; почему отложенные остатки не вошли (нет точной комбинации,
   приоритет, недоступны по Ozon). Подбор ничего не меняет. Просьба с объёмом и датой («6000 шт на 05.11») — согласие
   поставить слот (шаг 6); спросить один раз, если у взятой заявки берутся не все поставки или точной суммы нет.
5. **Свежая проверка** перед выдачей: снова `supplies_orders_get` по выбранным заявкам — статус, количество, слот, все
   места и их состав. Изменилось — остановиться и подобрать заново.
6. **Таймслот, водитель.** Нет водителя и машины (`needs_vehicle`) — `supplies_orders_vehicle_set` (навык
   `supplies-orders`). Нет слота (`needs_timeslot`) или он не подходит — навык `supplies-orders` (`supplies_orders_timeslots_list` →
   `supplies_orders_timeslot_set`). С первым таймслотом Ozon считает «Точность отгрузок» по **всем** поставкам заявки:
   не отгруженные к слоту — 0 из максимума. Берутся не все поставки заявки — сказать это до выбора слота и спросить.
7. **Этикетки** — только выбранных поставок, одним набором по навыку `supplies-cargoes` («Этикетки»): в
   `supplies_cargo_labels_bundles_create` — каждая выбранная поставка без `cargo_ids`. Все PDF — сразу, имена не менять;
   места без этикеток (`missing`) назвать.

## Ответ

Точная сумма; число уникальных и повторных кластеров; заявки ссылками
`[<order_number>](https://seller.ozon.ru/app/supply/orders/<order_id>)`; даты слотов (время точки отгрузки); грузоместа
по городам; по каждому файлу этикеток — города и число мест; частично взятые заявки и их остаток; отложенные остатки с
причиной. Одной фразой — откуда известно уже взятое: из этого разговора или только по статусам поставок. Отменённые,
просроченные и пропавшие остатки — отдельно, не как отгруженные. Выдача этикеток — не отгрузка: физическая отгрузка —
отдельное подтверждение пользователя.
