# Отчёт по отгрузкам FBO

Источник — строки `supplies_items_list` (строка — товар поставки). Отчёт — таблицы Markdown в ответе или файл, если
пользователь просит; в Notion и другие внешние места не публиковать.

## Шаги

1. **Товар.** По названию — `products_list` с `search`; несколько карточек — показать и спросить или взять все по
   просьбе. По артикулу — сразу `offer_id`. Товар не назван — все товары магазина.
2. **Строки.** `supplies_items_list` с `sku` или `offer_id` (одно значение за вызов),
   `supply_states=ACCEPTED_AT_SUPPLY_WAREHOUSE,IN_TRANSIT,ACCEPTANCE_AT_STORAGE_WAREHOUSE,REPORTS_CONFIRMATION_AWAITING,REPORT_REJECTED,COMPLETED`,
   `date_from`/`date_to` — **день таймслота** (дата отгрузки в поясе точки), `limit=500`, все страницы по `offset` до
   `total`.
   - Статус — **каждой поставки** (`supply_states`, в строке `supply_state`): в мультизаявке поставки живут по-разному.
     `states` — статус заявки, для отчёта не годится: в заявке на согласовании актов бывают ещё не отгруженные поставки.
   - «На точке отгрузки» (`ACCEPTED_AT_SUPPLY_WAREHOUSE`) — уже отгружено продавцом: без него недосчёт тысяч штук.
   - `sync_pending` или `streams[].last_success_at: null` — заявки ещё не загружены: так и сказать, не «0 шт».
3. **Отчёт.**
   ```bash
   python3 scripts/shipped_report.py in.json   # {"items": [...], "period": {"from", "to"}, "date_basis": "timeslot",
                                               #  "group": ["product","month","state","order","cluster","warehouse","date_state"]}
   ```
   Скрипт считает по `supply_state` и печатает Markdown: итог и таблицы групп `group` (по умолчанию `product`, `month`,
   `state`); по дням — `date_state` (сводная «дата × статус»). Всё — из строк, без лишних чтений. «По статусам и датам
   заявок» — `["date_state"]` или `["order","state"]`; заявки, давно висящие на точке отгрузки или на приёмке, назвать
   отдельно. «Что я подал с даты X» — по дате создания заявки: `date_basis: "created"`, и тогда `date_from`/`date_to` в
   шаге 2 не ставить (они по таймслоту) — период отфильтрует скрипт.
4. **Фасовка** («сколько отгружено коробками по N шт»): по каждой заявке из строк — `supplies_orders_get`, ответы — в
   `"orders"` входа скрипта. Считается по поставке и товару, только места с этим товаром: все по N — фасовка N, иначе
   «смешанная»; места, где он лежит вместе с другими товарами, — отдельной строкой. Таблица: товар, фасовка → мест,
   штук, дни отгрузки.

## Что ещё сказать

- Какая дата: день отгрузки по таймслоту (время Москвы) или дата создания заявки при `date_basis: created`. Строки без
  даты скрипт показывает отдельно.
- **FBS** этим отчётом не считается: отправления FBS — `orders_list` (`scheme=fbs`, `sku` или `offer_id`,
  `date_from`/`date_to` — дата создания, `status=sent_by_seller,driver_pickup,delivering,delivered` — переданные в
  доставку; без `status` в счёт попадут несобранные и отменённые), все страницы. По складам — `warehouse_name`, по дням
  — `shipment_date` (МСК), штуки — `products[].quantity` этого товара. Спросили «сколько всего отгружено» — FBO + FBS и
  общий итог.
