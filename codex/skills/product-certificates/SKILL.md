# Сертификаты и декларации

Документ качества у Ozon — отдельно в каждом магазине: декларация или сертификат и привязанные к нему карточки. С 01.10.2026
товары, которым нужен документ, Ozon продаёт только после проверки документа.

Seller AI создаёт документ **только данными**, без файлов: тип, стандарт, страна, номер, даты и ссылка на запись в
реестре. По ссылке Ozon сам проверяет документ — так же работает кабинет Ozon. PDF и фото не загружаются.

## Посмотреть

| Задача | Инструмент |
|---|---|
| Документы магазина: тип, статус, срок, сколько товаров | `products_certificates_list` |
| Один документ и его товары: артикул, SKU, проверка привязки | `products_certificates_get` (`certificate`) |
| Охват ассортимента, «Товары без сертификатов» | `products_certificates_coverage` |
| То же по нескольким магазинам или группе | `combined_products_certificates_list`, `combined_products_certificates_coverage` (`stores`) |

- Фильтры списка:
  - `state`: `valid`, `expiring` (до конца меньше 30 дней), `pending` (Ozon проверяет), `expired`, `declined`;
  - `type` — `declaration`, `certificate_of_conformity` и т. д.;
  - `sku`, `offer_id`, `product_id` — документы товара;
  - `expires_to` — истекают до даты;
  - `search` — номер или название.
- Срок — `expire_date` (день МСК) и `days_left`. `expire_date: null` — бессрочный. Отказ Ozon — `rejection_reason.name` и
  `verification_comment`: назвать их.
- `products: null` — товары документа синхронизация ещё не прочитала: «пока неизвестно», не «нет товаров».
- Охват: у каждой карточки `state` по лучшему документу (`valid` → `expiring` → `pending` → `expired` → `declined`),
  `none` — документа нет. `counts.covered_percent` — доля карточек с действующим документом. `counts_complete: false` —
  каталог или товары документов ещё грузятся: числа неполные, так и сказать.
- Отчёт по магазинам: один вызов `combined_*` со всеми ID из `stores_list` (или магазинами группы из `store_groups_list`).
  У строк — `store_id`. Магазин не `ok` в `stores` ответа — назвать его.

## Новый документ

1. **Данные документа.** Тип, стандарт, страна выдачи, номер как в реестре, дата выдачи, срок (дата или «бессрочный»),
   ссылка на запись в реестре.
   - Берутся из слов пользователя или из присланного файла: агент сам читает в нём номер и даты. Файл никуда не загружается.
   - Ссылка на запись в реестре: Росаккредитация — pub.fsa.gov.ru, ЕАЭС — tech.eaeunion.org. Без ссылки Ozon может
     попросить файл.
   - Название видит только продавец. Не задано — им будет номер.
2. **Что нужно Ozon.** `products_certificates_params` с `certificate_type`, `accordance_type`, `certificate_country` (и
   тем, что уже известно).
   - `missing` — чего не хватает: спросить у пользователя одним сообщением.
   - `outside_variants` — значение, которого Ozon не принимает; допустимые — в `allowed`.
   - `files_required: true` — Ozon требует файл: Seller AI такой документ не создаст. Сказать пользователю: добавить
     ссылку на реестр, если она есть, или загрузить документ в кабинете Ozon («Товары → Сертификаты качества»). Затем
     отправить запрос функции (навык `feedback`).
   - Коды типов и стандартов — `products_certificates_reference` (`options` — все поля с вариантами).
3. **Товары.** Пользователь называет артикулы, SKU или товары словами. Найти карточки: `products_search` (`field`:
   `offer_id` или `sku`) или `products_list` с `search`. Не нашлось — назвать и не придумывать.
4. **Создать.** `products_certificates_create`: поля документа и `skus` / `offer_ids` / `product_ids`, до 1000 товаров.
   - Ozon привязывает товары при создании по SKU. У карточки без SKU — 422 `no_sku`: создать без неё и потом привязать
     `products_certificates_bind`.
   - Полная просьба («добавь декларацию № … от … до … к орехам») — уже согласие. Чего-то не хватает — спросить один раз.
5. **Результат.** Операция `succeeded` → `certificate_id`. Документ появился у Ozon со статусом «Ожидает проверки». Ozon
   проверяет его и каждую привязку часами: статусы — в `products_certificates_get`.

Ответы создания:
- 409 `certificate_exists` — в магазине уже есть документ с этим номером (`certificate_id`): привязать товары к нему.
- 422 с `items`: `required` (поле нужно Ozon), `invalid` (вне `allowed`), `files_required`, `not_in_catalog`.
- Операция `failed` с отказом `incomplete` — Ozon отклонил поля: в `acknowledged` у элемента поля, их состояние (`INVALID`,
  `MISSING`), слова Ozon и маски номера. Исправить номер по маске и создать снова с новым `idempotency_key`.

## Несколько магазинов

Документ — у каждого магазина свой. «Добавь декларацию во все магазины»:
1. Найти нужные товары в каждом магазине. Артикулы одни и те же — `combined_products_list` с `search` по артикулу и всеми
   `stores`. Иначе — по магазину.
2. Создать документ в каждом магазине, где есть такие товары: `products_certificates_create` со своим `store_id` и своими
   SKU. Если в магазине документ с этим номером уже есть (409 `certificate_exists`), привязать к нему недостающие товары.
3. Отчёт — `combined_products_certificates_list` с `search` по номеру. Таблица: магазин, документ, статус, товаров
   привязано, что пропущено и почему.

## Привязать и отвязать

- Привязать — `products_certificates_bind` (`certificate`, тело `product_ids` / `skus` / `offer_ids`). Обратимо: полная
  просьба — согласие. Уже привязанные товары Seller AI пропускает: они в `skipped` операции, назвать их.
- Отвязать — `products_certificates_unbind` с `"confirm": true` — **только после явного «да»**. Товар, которому нужен
  документ, может уйти из продажи. Показать документ и товары, затем отправить.
- Готово, когда операция `succeeded`: синхронизация прочитала товары документа. Отказ Ozon по товару — у элемента
  `rejected` со словами Ozon: назвать.

## Удалить документ

`products_certificates_delete` с `"confirm": true` — **только после явного «да»**. Нужно право удаления (владелец или
администратор, у токена — `products: manage`). Показать номер, срок и сколько товаров его лишится. Истёкший документ удалять
не нужно: Ozon перестаёт его учитывать сам, главное — вовремя добавить новый.

## Ответы и ошибки

- 403 `forbidden` — нет права (`products.write`, удаление — `products.manage`): права выдаются в «Настройки → MCP и API» или их
  нет у роли пользователя.
- 409 `ozon_key_missing_method` — у ключа Seller API в Ozon нет роли с методами сертификатов: пользователь добавляет роль
  ключу в кабинете Ozon.
- 409 `certificates_stale` — Ozon не прочитался перед командой, ничего не отправлено: повторить через `retry_after` с тем же
  `idempotency_key`.
- 409 `target_busy` — у документа уже идёт другая команда: дождаться её.
- Категории, которым Ozon требует документ, — `products_certificates_categories` (`required=true`). Бренды, которым нужен
  документ, — `products_certificates_brands`.
