# Комиссии Ozon по категориям

Два источника, по точности:
1. **Ставка карточки магазина** — что Ozon отдаёт в карточке сейчас, уже с индивидуальными условиями (ИУ) магазина. Для
   существующего товара — только она.
2. **Справочник Ozon** `references/commissions-2026-08-28.tsv` — «Таблица категорий и типов для расчёта вознаграждения с 28
   августа 2026 г.». Для нового товара без карточки и для сверки.

## Ставка товара магазина

- **Сейчас** («какая комиссия у товара») — `prices_products_get` (`product`): `manager.expenses.fbo|fbs|rfbs` —
  `commission_pct` (процент карточки, уже с ИУ) и `commission` (рубли от `base` — цены с акциями продавца).
- **В плане** — `unit_economics_plan_list` (`scheme=FBO` или `FBS`): `inputs.commission_micro` (цена ≤ 100 ₽),
  `commission_low` (100–300 ₽), `commission_high` (> 300 ₽) — доли (`0.4` = 40 %); `commission_rate_manual` — ручная ставка на
  любую цену. Откуда ставка — `sources.commission_*`: `api_commission` (карточка Ozon), `store_rule` (правило ИУ),
  `store_rates` (одна ставка магазина во всех диапазонах), `category_table` (справочник). `commission_tariff` — строка
  справочника категории карточки; `computed.commission_rate` — ставка при цене плана; `commission:no_rate` — ставки нет нигде.
- **По магазину** — `stores_commission_rules_list`:
  - `detected[]` — ставки карточек сейчас по схеме (`FBO`, `FBS`) и диапазону (`micro` ≤ 100, `low` ≤ 300, `high` > 300) с
    числом карточек. Одна ставка во всех диапазонах вместо обычных 17 / 23 / 40 % справочника — признак ИУ; ставки не из
    справочника (в том числе дробные) — тоже повод спросить про ИУ;
  - `rules[]` — ИУ, записанные в Seller AI: схема, категория (или все), цена `(price_from, price_to]`, ставка, с даты. Из правил
    одного товара действует последнее по дате, среди правил одного дня — самое узкое;
  - `categories[]` — категории и типы карточек магазина — для правила ИУ.
- **В рублях при текущей цене** — `prices_products_list` (`tab=expenses`): `expenses.base` — цена с акциями продавца, от
  которой Ozon считает вознаграждение; `fbo` / `fbs` / `rfbs` — расходы схемы (вознаграждение + эквайринг + логистика) в
  рублях, как в кабинете.
- **Факт удержаний** — `unit_economics_accruals_list` (`amounts.commission` товара) и `finance_accruals_list` (у строки продажи
  `children[].commission_ratio` «Вознаграждения за продажу» — ставка, которую Ozon применил, долей).

Ставка фиксируется по дате заказа: после смены условий в начислениях одной недели — смесь старых и новых ставок, это не
ошибка.

## Справочник для нового товара

Искать скриптом — подстрокой без регистра в «Категории» и «Типе товара»:

```sh
python3 scripts/commission_lookup.py "сухофрукт" --price 450 --scheme fbo
```

- `--scheme fbo|fbo_fresh|fbs|rfbs` (по умолчанию `fbo`): у `rfbs` одна ставка на любую цену, у мототехники дороже 500 000 ₽ —
  своя. `--field type|category` — искать только в типе или в категории. `--json` — строки со ставками долями
  (`commission_micro`, `commission_low`, `commission_high`) для юнит-экономики нового товара. `--tsv <файл>` — другой
  справочник.
- Не нашлось — родственные слова (сушёный → сухофрукты, конфеты → конфета), затем категория выше.
- Списки — прямо из файла: все категории — `cut -f2 references/commissions-2026-08-28.tsv | sort -u`; типы категории —
  `awk -F'\t' '$2 == "Сухие завтраки, снэки, суперфудс" {print $3}' references/commissions-2026-08-28.tsv`; точный тип —
  `awk -F'\t' '$3 == "Конфеты"' references/commissions-2026-08-28.tsv`. Ставки в файле — в процентах; пустая ячейка — у Ozon
  ставки нет.
- Диапазон — по цене продавца с его акциями: ≤ 100 ₽, 100–300 ₽ (выше 100 и до 300 включительно), > 300 ₽. Переход цены через
  100 или 300 ₽ меняет ставку сразу.
- Ответ — ставка в процентах и в рублях (`цена × ставка`) со строкой справочника.

**Новая таблица Ozon.** XLSX «Таблица категорий и типов для расчёта вознаграждения» (ссылка — в статье
`full-actual-commissions` навыка `ozon-edu`; файл скачивает пользователь) → справочник:

```sh
python3 scripts/table_from_xlsx.py <файл.xlsx> --from 2026-10-07    # → references/commissions-2026-10-07.tsv
```

Шапка не как у Ozon — код 1: файл не тот. Скрипт поиска берёт самый новый справочник; для заказов до новой таблицы — `--tsv`
прежнего файла.

## Факты Ozon

- С 28.08.2026 у товаров дороже 300 ₽ одна ставка на основную категорию (продукты питания — 40 %); дешёвые — почти везде 17 %
  (до 100 ₽) и 23 % (100–300 ₽).
- Тарифа «Эконом» (кванты) нет с 31.03.2026: флага у карточки нет, «эконом» в речи продавцов — нижние диапазоны цены.
- «Благотворительность» в справочнике — 1 %, но без верификации НКО Ozon берёт обычную ставку категории.
- Таблица Ozon с 07.10.2026 и новая формула вознаграждения с отменой баллов за скидки с 01.12.2026 в навык не загружены: для
  нового товара сказать, что ставка — по таблице от 28.08.2026, и сверить с калькулятором кабинета; есть у пользователя XLSX
  новой таблицы — загрузить его («Новая таблица Ozon»).

## Индивидуальные условия: запись

`stores_commission_rules_save_many` **заменяет весь набор** правил магазина: прислать все прежние (с их `id`) и новое. Полная
просьба (схема, категория или все, цена, ставка, с даты) — записать и показать таблицу «правило: схема, категория, цена,
ставка, с даты — было → стало»; чего-то нет — спросить один раз. Это данные Seller AI (план и факт пересчитаются), в Ozon
ничего не уходит. ИУ записывают, когда их не видно из API: будущая дата соглашения, отдельные категории.
