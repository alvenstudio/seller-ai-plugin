# Юнит-экономика

Seller AI считает план и факт сам (seller-ai-docs `architecture/economics-v2.md` §2–§6, `unit-economics.md`): авто-входы — из
истории магазина, формула плана — версия 5 (`plan-formula.schema.json` контрактов), одна у сервера и у веба. Агент читает
посчитанное, объясняет и сохраняет правки (полная просьба — согласие, см. ниже). Скрипт нужен только для товара, которого ещё
нет в Ozon.

## План по товарам магазина

`unit_economics_plan_list` (`scheme=FBO` по умолчанию или `FBS`; `status=in_sale,to_supply,removed_from_sale,other` — без него все
строки; пользователю обычно нужно `in_sale`). Строка — живая карточка × схема, статистика — главного SKU:

- `inputs` — входы формулы (ручные поверх авто), `auto` — авторасчёт, `overrides` — ручные значения в силе, `sources` — откуда
  авто-значение, `basis` — выборка, окно, значение магазина, вес;
- `computed` — шаги на **выкупленную** единицу: `commission`, `acquiring`, `logistics_total`, `disposal_fees`, `total_ozon`,
  `advertising`, `payout`, `early_payout`, `vat`, `tax`, `profit`, `margin` (к цене), `profitability` (к себестоимости);
- `cluster_details[]` (FBO) — тариф каждого кластера доставки и ценового бакета с долей рынка; `inputs.logistics_overpay` —
  переплата за раскладку остатков против идеальной (товар в каждом кластере);
- `warnings`: `cost:missing`, `cost:ozon_net_price`, `commission:no_rate`, `supply:no_accruals_yet`, `buyout:store_prior`,
  `missing:<вход>`; `coverage.incomplete_rows` — строки без прибыли (например, нет ставки налога — `missing:tax_rate`);
- `ozon_prices {price, old_price, min_price, marketing_seller_price}` — цены карточки в Ozon, `actions {current, candidates}` —
  акции товара, `in_scheme {stock, sold_28d}` — продаётся ли он по этой схеме.

**Формула v5 (на выкупленную единицу).** `P` — цена с акциями продавца (`marketing_seller_price` больше 0, иначе `price`, но не выше
`price`); `B` — выкуп; `c₀` — отмены до отгрузки.

| Шаг | Формула |
|---|---|
| Вознаграждение | `P × ставка` диапазона цены: ≤ 100 ₽ `commission_micro`, ≤ 300 ₽ `commission_low`, выше `commission_high`; ручная `commission_rate_manual` — на любую цену |
| Эквайринг | `P × acquiring_rate` |
| Логистика с невыкупами | `(Л + М) / B + (1 − B) / B × (Л_обр + обработка)`; `Л` — тариф бакета цены (≤ 300 ₽ — `logistics_lt_300`, выше — `logistics_gte_300`), `М` — последняя миля и обработка отправления |
| Прочее Ozon | поставка (кросс-докинг, FBO), размещение (0, пока не задано), `disposal_share × disposal_fee`, `P × stars_rate`, `P × insurance_rate`, прочие сборы |
| Реклама | `P × ДРР / ((1 − c₀) × B)` — ДРР целевой, к выручке заказов |
| Выплата Ozon | `P − ИТОГО Ozon − реклама` |
| Досрочная выплата | `выплата × r / (1 + r)` (комиссия с суммы, которая приходит на счёт; выплата ≤ 0 — 0) |
| Доход, НДС | доход — `P × (1 − баллы%)` (база `revenue`, `profit`; баллы за скидки равны ставке вознаграждения строки, `points_share = commission_rate`) или `P` (`sales`); НДС = `доход × НДС / (1 + НДС)` |
| Налог | `ставка × (доход − НДС)`; при базе `profit` — от прибыли до налога; база ≤ 0 — 0 |
| **Прибыль** | `выплата − досрочная − себестоимость − u × себестоимость − прочие расходы − НДС − налог` |

**Авто-входы (откуда цифры).** Выкуп и отмены — зрелые когорты заказов 90–14 дней назад, сжатые к значению магазина (молодая
карточка получает выкуп магазина, по умолчанию 0,93); утилизация — медиана трёх 30-дневных окон (разовые массовые списания не ломают
план), у магазина с малым числом выкупов сжатая к 0 (k = 200 выкупленных единиц: у нового магазина несколько списаний не
дают 100 %); последняя миля, обратная логистика, эквайринг, прочие сборы — по начислениям 28 / 90 дней; баллы за скидки равны
ставке вознаграждения и не правятся; логистика FBO —
кластерная модель по реальным остаткам; кросс-докинг — по принятым поставкам текущего остатка; ставка вознаграждения — правило ИУ
магазина → ставка карточки Ozon → частая ставка магазина в категории и диапазоне → справочник категорий. **Целевой ДРР не
рассчитывается** — его задаёт продавец (не задан — 0, источник `not_set`; фильтр «без целевого ДРР» — такие строки). Отправная
точка для цели — фактический общий ДРР товара за 28 закрытых дней: `promotion_analytics_get` (`slice=product`, `skus`,
`metrics.drr` — проценты; `gmv.covered: false` — неизвестен); предложить его и сохранить `unit_economics_plan_save_many`
(`drr` долей), когда пользователь согласен или сам просит «поставь ДРР как по факту». Размещение — 0,
пока не задано вручную. «Звёздные товары» и досрочная выплата — из настроек магазина, иначе по начислениям (в строке не правятся).

**Сценарий без записи** — `unit_economics_plan_preview` (`scheme`, `product_id`, `price`, `drr`, `cost {value, effective_from}`,
`overrides`): строка с черновиком поверх сохранённого. Так отвечать на «что будет при цене X / ДРР Y / выкупе Z»; цена перешла через
100 / 300 ₽ — меняются ставка и бакет логистики сразу. Обратные вопросы (цена при целевой прибыли, предельная себестоимость) —
несколькими preview.

**Сохранить план** — `unit_economics_plan_save_many` (`scheme`, `items[{product_id, expected_revision, price?, drr?, cost?,
overrides?}]`): только изменённые поля; `null` возвращает цену к цене карточки, ДРР — к «не задан», ручное значение — к авторасчёту.
`drr` — доля (`0.12`). Ручные входы (свои у схемы): `buyout`, cancel_before_ship (отмены до отгрузки), `disposal_share` (качество упаковки = 1 − доля),
`disposal_fee`, `last_mile`, `logistics_lt_300`, `logistics_gte_300`, `reverse_logistics`, `return_processing`,
`supply_cost`, `placement`, `commission_rate_manual`, `acquiring_rate`, `insurance_rate`, `other_ozon_fees`; общее —
`other_unit_cost`. Полная просьба («поставь курагам ДРР 12 %») — согласие: сохранить и показать «было → стало» с
пересчитанной прибылью; «что будет, если…» — только preview, без записи; неоднозначно (какой товар, какая схема) —
спросить один раз. Ответ: `saved` и
`conflicts[{product_id, revision}]` — товар изменили после чтения: перечитать, показать заново. Цель биддера «ДРР из плановой
юнит-экономики» подхватывает новый ДРР сразу.

**Цена в Ozon.** Цена плана `P` — с акциями продавца; в Ozon меняется `price` («Предельная цена без акций») командой
`prices_values_set` (`items[{product_id, price, old_price, min_price, expected {price, old_price, min_price}}]`, цены — строки рублей `"259.00"`, `expected` — из
`ozon_prices` строки). Это команда в Ozon: показать «сейчас → новая», предупредить (покупатели увидят цену сразу; могут измениться
индекс цен, участие в акциях и цена с акциями); полная просьба («поставь 259 ₽») — согласие, иначе спросить один раз; одна
команда на намерение с `idempotency_key`; 200/202 —
`operations_get` до `succeeded`, `outcome_unknown` не повторять. Изменение больше чем на 50 % — только владелец и с
`confirm_large_change: true`; 409 `stale_expected` — цена уже другая, перечитать; `price_change_limit` — Ozon принимает 10 изменений
цены в час на товар. Цену с акциями Ozon пересчитает сам (~15 минут), план увидит её после чтения цен. С включённой «Минимальная
цена = Ваша цена» (`prices_automation_get`) `min_price` не менять: Seller AI выставит её равной новой цене сам за несколько минут.

## Факт по товарам

- **«По начислениям»** — `unit_economics_accruals_list` (`from`, `to` ≤ 366 дней, `scheme`, `allocate`, `cost_method`): прибыль
  товара за период по начислениям Ozon, сходится с итогом магазина. Сравнивать с планом на единицу: `accrued / units.net` против
  `computed.payout`, `profit_per_unit` против `computed.profit` (план — на выкупленную единицу, факт — на нетто проданную).
- **«Как в Ozon»** — `unit_economics_actual_get` (`from`, `to`, `scheme`, `sku`, `search`): копия раздела кабинета — отгружено,
  доставлено, возвращено, продажи, вознаграждение, логистика, реклама по видам, прибыль кабинета.

## Себестоимость

- По периодам — `cost_prices_list` (`search`): у карточки `current {cost, effective_from, source}`, `previous`, все `periods`;
  `ozon_net_price` — `net_price` карточки в Ozon (0 у Ozon — «не задана», не ноль). Записать —
  `cost_prices_save_many` (`changes[{product_id, effective_from, cost}]`, `cost: null` удаляет период): период действует со своей даты
  до следующего, прошлые дни пересчитываются. Себестоимость с датой («курага 400 — 180 ₽ с 01.10») — согласие: записать и
  показать таблицу «товар — было → стало — с даты»; дата не названа — спросить один раз (с сегодня или с другой даты).
- По партиям поставок (эксперимент, только FBO) — `cost_batches_list`: без `sku` — сводка по SKU (`batches`, `ledger_remaining`,
  `ozon_stock`, `in_delivery`, `difference` — расхождение журнала с остатком Ozon, `remaining_avg_cost`); с `sku` — партии (поставка,
  дата приёмки, кластер, принято «по акту» или «по заявке», осталось, цена и её источник), журнал движения, сравнение себестоимости
  проданного по периодам и по партиям. Цена партии — `cost_batches_save_many` (`changes[{supply_id, sku, unit_cost}]`, `null` —
  обратно к цене периода), по полной просьбе или после «да». Метод магазина (периоды / партии) — в настройках.

## Настройки экономики магазина

`stores_economics_settings_list` — версии с датами (новые первыми, `in_force` — действующая сегодня, `auto` — что план берёт для
пустых «Звёздных» и досрочной), `stores_economics_settings_get` — действующая сегодня. Поля: `tax_rate`, `tax_base`
(`revenue` | `sales` | `profit`), `vat_rate` (0 / 5 / 7 / 10 / 22 %), `cost_method`, `other_unit_cost` (упаковка, маркировка,
доставка до склада, ₽ на единицу), `default_buyout`, `stars_rate` (доля цены), `early_payout_rate` (доля выплаты на счёт; своя у
магазина: например, «на следующей неделе» Ozon Банк 2,91 %, другие банки 3,89 %; стандартный график — 0; API её не отдаёт).

Записать версию — `stores_economics_settings_save`: обязательно `effective_from`, `packaging_quality`, `default_buyout`,
`flat_commission` (взять из версии, действующей на эту дату); поле, которого нет в теле, сохраняет прежнее значение, `null`
очищает. Версия с прошлой даты пересчитает налог и прибыль прошлых дней, будущая — вступит в силу в свой день. Удалить —
`stores_economics_settings_delete` (`effective_from`): с её даты снова действует предыдущая версия. Обе — по полной просьбе
(значение и дата названы) или после «да»; какие дни пересчитаются — сказать в ответе.

Индивидуальные условия по вознаграждению — `stores_commission_rules_list` / `stores_commission_rules_save_many` (подробно — навык
`category-commissions`).

## Новый товар без карточки

Seller AI считает только карточки магазина. Для идеи товара — `scripts/new_product_plan.py`: та же формула v5
(`references/plan-formula.schema.json`, проверена векторами паритета контракта), логистика FBO по справочнику тарифов Ozon
`references/logistika-fbo-fbs.xlsx` (матрица с 28.08.2026) и фиксированным долям рынка кластеров
`references/cluster_market_share_defaults.json`.

1. Собрать `product.json`: `price`, `cost`, `volume_liters` (габариты в мм: `высота × ширина × глубина / 1 000 000`), `drr` (доля),
   `commission_micro`, `commission_low`, `commission_high` (справочник `category-commissions`; у магазина с ИУ — его ставки из
   `stores_commission_rules_list`); при желании любые другие входы формулы.
2. Сохранить ответы `stores_economics_settings_get` (налог, НДС, выкуп по умолчанию, прочие расходы) и `unit_economics_plan_list`
   магазина (медиана его строк — выкуп, отмены, последняя миля, эквайринг, утилизация, досрочная). Кросс-докинг растёт с
   объёмом: объём товара × медиана «`supply_cost` ÷ `volume_liters`» строк магазина с поставками, без них — объём × 15 ₽
   (`sources.supply_cost`: `store_per_liter` или `default_per_liter` — назвать).
3. Запустить:

```sh
python3 scripts/new_product_plan.py --inputs product.json --settings settings.json --plan plan.json \
    --clusters "Москва, МО и Дальние регионы" "Казань"      # где будет лежать товар; без --clusters — идеальная раскладка
```

`--json` — входы с источниками, шаги, тарифы по кластерам. В ответе пользователю показать: объём и его диапазон, кластеры с товаром,
какие продажи локальные, средний тариф для бакета цены и переплату за раскладку, применённую ставку вознаграждения, прибыль с
единицы, маржу и рентабельность; входы «по умолчанию» назвать.

**Кластерная модель (как в Seller AI).** Для каждого кластера доставки из справочника долей: есть товар в нём — продажа локальная,
тариф «кластер → тот же кластер»; нет — самый дешёвый маршрут из кластеров с товаром; маршрута нет в матрице — тариф по умолчанию
диапазона объёма. Средний тариф = Σ тариф × доля рынка, отдельно для товаров до 300 ₽ и от 300 ₽ (с 28.08.2026 маршрут влияет и на
дешёвые). Доли рынка — зафиксированный пользователем справочник: не подменять долями из API без его просьбы. Объём — первый
диапазон Ozon, верхняя граница которого не меньше объёма (между «X» и «X,001» есть зазор).

## Условия Ozon (с датами)

| Условие | Состояние |
|---|---|
| Наценка за нелокальную продажу | 0 % с 9 июля 2026 для всех кластеров (механизм в документах Ozon сохранён) |
| Тарифы логистики FBO | матрица с 28.08.2026: дальние маршруты дорогих товаров +14–47 %, локальные без изменений; дешёвые (< 300 ₽) — тариф зависит от маршрута; новая матрица FBO/FBS объявлена с 30.10.2026 (файл ещё не загружен) |
| Вознаграждение | с 28.08.2026: > 300 ₽ — одна ставка на основную категорию (продукты питания 40 %), 100–300 ₽ — 23 %, ≤ 100 ₽ — 17 %; фиксируется по дате заказа |
| Фиксация тарифов | тарифы логистики и кластер поставки — на 60 дней от создания заявки (план считает по текущей матрице) |
| Последняя миля | партнёрами — не больше 25 ₽, силами Ozon — 25 ₽; факт 7–12 ₽ (FBS с обработкой ~10–11 ₽) |
| Обработка невыкупа | 15 ₽ партнёрами |
| Утилизация | сбор 75 ₽ за единицу по умолчанию (Ozon считает за кг: 25 или 75 ₽/кг, не меньше 1 кг) |
| «Звёздные товары» | Ozon подключает сам, ~1,5 % от цены заказа — в плане по начислениям или из настроек |
| Страхование остатков | Ozon отменил с 13.10.2026 |
| Баллы за скидки | в плане равны ставке вознаграждения товара (формула v5, 28.10.2026) и вручную не задаются (`points_share` в `overrides` — 422); Ozon объявил отмену баллов и новую формулу вознаграждения с 01.12.2026 — тогда правило пересмотрят |

Если Ozon снова меняет условия — начинать с дайджестов и «Комиссий и тарифов» в выгрузке Ozon Edu (навык `ozon-edu`).

## Важно

- ДРР — общий ДРР (весь рекламный расход к всей выручке товара), не логистика. Проценты в API плана — доли (`0.08`), в рекламе —
  проценты (`8`).
- Для существующего товара в ответе всегда показывать: источник себестоимости, применённую ставку вознаграждения и её источник,
  выкуп и его основание, логистику бакета цены и переплату, предупреждения строки.
- `null` — неизвестно, не 0; прибыль без ставки налога — неизвестна.
