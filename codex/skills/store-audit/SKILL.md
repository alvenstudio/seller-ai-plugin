# Аудит магазина Ozon

Три шага: ответы инструментов Seller AI — в файлы → `scripts/build_report.py` сводит их в `report.json` → `scripts/render.py` рисует
презентацию. Скрипты ничего не запрашивают, только считают и рисуют.

## 1. Уточнить

- **Магазин и период** (дни МСК). Длинный период — одним окном: отчёты берут любой загруженный период.
- **Себестоимость** (её и налога нет в Ozon). `cost_prices_list`: товары без себестоимости (`current: null`) и «из Ozon» (`source:
  ozon_net_price`) — попросить недостающее (таблицей или картинкой — расшифровать) и записать `cost_prices_save_many`
  (`changes[{product_id, effective_from, cost}]`). Присланная таблица с датами — согласие, в ответ — «было → стало»; расшифровка
  неуверенная или дат нет — показать и спросить один раз.
- **Налог** — `stores_economics_settings_list` (ставка, база и НДС по датам). Ставки нет — спросить и записать версию
  `stores_economics_settings_save` (названная ставка с датой — согласие). УСН + НДС + прочие удержания — эффективная ставка.
- **Магазины того же ИП.** `stores_seller_info_get` — юрлицо, `company.inn` и система налогообложения (на обложку — файлом `--seller`).
  Вызвать его у каждого магазина из `stores_list`: одинаковый `inn` — один налогоплательщик, налог и порог НДС общие (на УСН в 2026 —
  20 млн ₽ по всему ИП, `references/pitfalls.md`). Назвать такие магазины и спросить, вести ли их налог строками `extra`; магазин
  другого ИНН в налог не складывать. `company: null` — реквизиты ещё не прочитаны: ИНН спросить.
- **Строки вне Ozon**, которые владелец знает сам (налог второго магазина того же ИП, выкупы маркетплейсом, ожидающие подписания…), —
  в `extra` конфига.

## 2. Собрать данные

Все месяцы периода в `stores_history_months_get` (`feature=store_economy`) должны быть `ready`; `loading` — сказать, что аудит будет
неполным, и подождать или сузить период.

Ответы — в файлы одной папки:

| Файл | Инструмент и аргументы |
|---|---|
| `profit-<окно>.json` | `economics_profit_get`: `from`, `to` (весь период одним окном или окна подряд без пересечений), `group=month`, `scheme=all` |
| `accruals-<окно>.json` | `unit_economics_accruals_list`: те же окна, `scheme=all`, `allocate=none` |
| `assets.json` | `assets_summary_get` (остатки и активы сейчас) |
| `batches.json` | `cost_batches_list` без `sku` (сверка остатка FBO с журналом партий) |
| `np-<страница>.json` | `finance_accruals_list`: `from`, `to` периода, `type_ids=6,40,45,59`, `page_size=200`, все страницы |
| `balance.json` | `balance_history_list`: `from`, `to` периода — нужны `totals` (`accrued`, `paid`, `end`) |
| `seller.json` | `stores_seller_info_get` |
| `removals.json` | `removals_list`: `date_from`, `date_to` периода, `limit=1` — нужны только `totals` и `coverage` |
| `dg-<страница>.json` | `decommissioned_goods_list`: `date_from`, `date_to` периода, `limit=500`, все страницы (`offset` до `total`) |
| `config.json` | составить: `{"store_id", "store_name", "extra": [{"label", "amount", "note"}]}` |

`np-*` — услуги «Возвратов и невыкупов» (6 отмена, 40 частичный возврат, 45 обработка возврата в ПВЗ, 59 обратная логистика): скрипт
считает уникальные отправления (`unit_number`), рубли берёт из категории отчёта. Без этих страниц — `non_pickup_count` в конфиге
(`total` ответа с `type_id=59`): это строки обратной логистики, а не отправления, — слайд так и подпишет.

```sh
python3 scripts/build_report.py --profit audit/profit-*.json --accruals audit/accruals-*.json \
    --assets audit/assets.json --batches audit/batches.json --non-pickups audit/np-*.json \
    --seller audit/seller.json --removals audit/removals.json --decommissioned audit/dg-*.json \
    --balance audit/balance.json --config audit/config.json --out audit/report.json
python3 scripts/render.py --report audit/report.json --out audit-out
```

`render.py` делает PDF (`Аудит <Магазин>.pdf`, страницы ровно 1080×1920), HTML-дек и PNG каждого слайда; `--no-pdf`, `--no-html`,
`--no-images` отключают. PDF и PNG печатает локальный headless Chrome (`--chrome` или `CHROME_PATH`); без него остаётся HTML.

## 3. Проверить и проговорить

- `build_report.py` печатает итог и предупреждения (они же — в `report.json` и в подвале HTML): товары без себестоимости и «из Ozon»,
  налог не задан, реклама по оценке, неполные вывоз и списания (`coverage.complete: false` — цифры неполные, а не нулевые), партии без
  себестоимости. Проговорить их пользователю: они меняют цифры.
- Расхождение сверки с «Начислениями» — дефект расчёта Seller AI: итог не выдавать за точный (обложка и подвал пометят цифры
  предварительными), назвать окно и сумму расхождения и предложить сообщить об ошибке (навык `feedback`).
- «Начислено» должно совпасть с «Балансом» за период (`totals.accrued` у `balance_history_list`, скрипт сверяет). Расхождение — услуги
  «Озон Технологии», которые «Баланс» ведёт отдельно, или начисления периода загружены не все (цифры занижены): сверить с кабинетом и
  сказать. «Выплачено» (`totals.paid`) ≈ «Начислено»: разница — остаток на площадке (слайд «До вас доходит»).
- Есть свой расчёт у пользователя — свериться по месяцам: расхождения — самая полезная часть аудита.
- Перед тем как спорить с цифрами — `references/pitfalls.md`.

## Презентация

Обложка с чистой прибылью, юрлицом и ИНН → «до вас доходит N %» → прибыль по месяцам → услуги Ozon по категориям и строкам → утилизация
по товарам и причины списаний → прибыль с единицы (от 20 проданных) → невыкупы и вывоз со складов → остатки по кластерам и активы →
материальный баланс FBO → строки владельца.

**Материальный баланс FBO** — «должно быть на Ozon» по журналу партий (принято по актам или по заявке, минус продажи, утилизация и вывоз,
плюс возвраты — за всю историю магазина, на сегодня, а не на конец периода аудита) против «есть у Ozon» (склады + доставка покупателям).
Разница > 0 — недостача, < 0 — излишек; только FBO. Акты приёмки приходят с опозданием, и партия без акта считается «по заявке» — частая
причина ложной недостачи. Недостача от 2–3 % принятого — сначала искать ошибку данных, а не воровство.

## Чего аудит не видит

- **Расходы вне Ozon** — фасовка, доставка до кросс-дока, зарплаты, изъятия владельца. Прибыль не сходится с деньгами на счёте — разница
  почти всегда здесь; закрывается выпиской по счёту и строками `extra`.
- **Налог других магазинов того же ИП** — аудит считает налог одного магазина: остальное строками `extra` или отдельным аудитом.
- Отгрузки с нулевой выручкой отдельно — пока недоступно в Seller AI; нужно пользователю — запрос функции (навык `feedback`).
