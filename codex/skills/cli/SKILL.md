# Seller AI из терминала

`scripts/seller_ai.py` (путь — от папки этого навыка) — клиент того же MCP-сервера Seller AI: те же инструменты под теми же
именами, тот же вход, согласия и проверки сервера. Отличие одно: вызывает его shell или скрипт, и модель видит только
напечатанное. Что проверять и о чём спрашивать — по навыку задачи (`supplies-cargoes`, `supplies-super`, `promo-daily`…);
этот навык меняет только способ вызова.

## CLI или MCP

| Задача | Чем |
|---|---|
| Одно-два чтения или одна команда, ответ нужен целиком | MCP |
| Одна операция по многим объектам — больше ~5 одинаковых вызовов (грузоместа 20 поставок, 300 цен, серия заявок) | CLI |
| Итог по большому ответу, многим страницам или магазинам: счёт, сумма, поиск, сверка | CLI: `--select` или скрипт |
| Ответ нужен скрипту навыка (`cargo_plan.py`, `super_plan.py`) или файлом на диске | CLI в файл |
| Нет терминала или из него нет выхода в интернет | MCP |

Пример: `supplies_orders_list` магазина с 50 заявками — 260 тыс. символов ответа через MCP, с
`--select 'items[].{order_number,state}'` — 2,7 тыс. Прочитанное CLI не перечитывать через MCP ради показа.

## Вход

```bash
python3 scripts/seller_ai.py status                   # кто вошёл и какие магазины; токен не печатается
python3 scripts/seller_ai.py login --code sal_…       # нет входа (код 4), а MCP Seller AI подключён
python3 scripts/seller_ai.py login                    # MCP нет и не будет: откроется браузер
```

- **Есть подключение MCP Seller AI** — сам, не спрашивая: `cli_codes_create` даёт одноразовый код на 2 минуты, сразу
  `login --code <код>`. Браузер и второе согласие не нужны, магазины и права — те же, что у подключения MCP. Код никому не
  показывать и в ответе не повторять; не принят — новый код.
- **Инструментов MCP Seller AI в сессии нет** — сначала сказать пользователю, что MCP не подключён, и как подключить: тогда
  вход один на MCP и CLI. Hermes — `hermes mcp add seller-ai --url https://seller.alven.studio/mcp --auth oauth` и
  `hermes mcp login seller-ai` (без них сервер плагина получает 401 и молча отключается); Claude Code — `/mcp` →
  `seller-ai` → вход; Codex — `codex mcp login seller-ai`. Подключили — вход кодом, как выше.
- **MCP нет и не будет** (клиент без MCP, пользователь отказался) — `login` открывает в браузере вход Seller AI: магазины и
  права выбирает пользователь. Ждёт до 10 минут — запускать с таймаутом команды 10 минут или в фоне; ссылка печатается в
  stderr — браузер не открылся, дать её пользователю. Без браузера (сервер) — токен из «Настройки → MCP и API»:
  `login --token` вводит сам пользователь. Токен в чате не просить и не печатать.
- Вход один на компьютер и продлевается сам; `logout` отзывает его.
- В пути бывают пробелы: в shell — функция `sa() { python3 "<папка навыка>/scripts/seller_ai.py" "$@"; }`, в Python —
  `sys.path.insert(0, "<папка навыка>/scripts"); import seller_ai`.

## Найти инструмент

`tools ТЕКСТ` — инструменты этого входа с пометкой `[r]` чтение, `[w]` команда, `[!]` необратимая. Описания английские:
искать по части имени или английскому слову (`tools supplies_cargo`, `tools cargo`). `help ИМЯ` — описание и аргументы.
Имена те же, что в MCP и в навыках.

## Вызов

```bash
python3 scripts/seller_ai.py supplies_orders_get store_id=S order=O --select 'supplies[].{supply_id,state}'
python3 scripts/seller_ai.py supplies_orders_get store_id=S order=O > order.json     # большой ответ — в файл
python3 scripts/seller_ai.py supplies_cargoes_set @call.json --wait                    # аргументы из файла
```

- Аргументы: `ключ=строка`, `ключ:=JSON` (`limit:=50`, `body:='{…}'`), `body.mode=add` (вложенное поле), JSON-объект,
  `@файл.json`, `-` (stdin). ID и номера — строкой (`order=12345678-1`).
- `--select`: `a.b`, `items[].id`, `items[].{id,name}`, `supplies[0].cargo_ids`, `{operation,warnings}`. Нет поля — `null`:
  «нет в ответе», не ноль.
- stdout — JSON одной строкой; ошибка — `{"error", "exit", "detail"}`, в `detail` ответ сервера (например `current` у 409,
  магазины входа, если нужен `store_id`). stderr — `warning <код>: …`: предупреждения сервера, как в MCP (ключ, данные ещё
  не загружены, команда открыта, `replayed`) — сказать пользователю.
- Файл ответа (PDF, xlsx) сохраняется (`--out ПУТЬ`, иначе в текущую папку; имена не затираются), печатаются путь и размер.
- Коды выхода: 0 готово (без `--wait` — и «команда принята, идёт»); 1 ошибка инструмента или команда закончилась не
  `succeeded`; 2 неверный вызов и 3 нужно `--yes` — оба ничего не отправили; 4 нужен вход; 5 сеть или сервер («команда
  могла уйти» — сначала проверить, ушла ли, потом решать); 6 позже, через `retry_after`; 7 команда ещё идёт после `--wait`.

## Команды

- Согласие — по навыку задачи: полная просьба — согласие на обратимые команды.
- **Необратимая** (`[!]`) без `--yes` не уходит: CLI печатает, что сервер собирается сделать (`needs_confirmation`), и
  выходит с кодом 3. Показать это пользователю и после явного «да» повторить с `--yes`. Без «да» `--yes` не ставить; «да»
  относится к названным объектам, не к следующим.
- `--wait` доводит команду до конца (операция, этикетки) и выжидает `retry_after`; готово — только `succeeded`
  (`outcome_unknown` — ещё не итог: Seller AI сверяет с Ozon, CLI ждёт дальше; команду поставок, которую притормозил лимит
  Ozon, — `waiting_quota` с `retry_at` — Seller AI отправит сам, CLI ждёт её, свой повтор не нужен). Без `--wait` печатается открытая операция,
  дальше — `operations_get` (у продвижения — `promotion_operations_get`).
- Повтор: ответа не было — CLI сам повторяет один раз, если команда это позволяет (с ключом идемпотентности или
  идемпотентная), иначе выходит с кодом 5. Свой ключ — `idempotency_key`: тот же ключ — та же команда, заново ничего не
  уйдёт (CLI скажет `replayed`). Намеренно одинаковым командам (одинаковые черновики серии) — каждой свой ключ
  (`series-2026-11-08-3`), повтор прежней команды по новой просьбе — новый ключ. `outcome_unknown` не повторять.

## Массовые действия

1. Прочитать в файлы, посчитать скриптом навыка по файлам; в контекст — только сводка.
2. Вызовы — JSON lines, строка на объект: `{"id": "<метка объекта>", "tool": "…", "args": {…}}`. Необратимой строке —
   `"yes": true`, только если пользователь сказал «да» именно на этот объект; общего `--yes` у `batch` нет.
3. План пользователю — что, сколько, где. `batch calls.jsonl --dry-run` печатает команды, ничего не отправляя (чтения
   идут, кроме выгрузок, которые заводят в Ozon задание на файл). Согласие — по навыку задачи.
4. `batch calls.jsonl --wait --select operation.status` — по строке на вызов `{"n", "id", "key", "ok", "result" | "error"}`;
   первая ошибка останавливает (`--keep-going` — идти дальше). С командами нужны метка `--run` (`series-2026-11-08`) и
   свой `id` у каждой: ключ команды — из метки, `id` и аргументов. Тот же запуск с той же меткой отправит только
   несделанное, исправленная строка уйдёт заново; новая просьба с теми же строками — новая метка. Шаг зависит от прошлого
   ответа — Python:

   ```python
   import sys; sys.path.insert(0, "<папка навыка>/scripts")
   import seller_ai
   sa = seller_ai.Client()                    # Client(dry_run=True) — команды не отправляются
   order = sa.call("supplies_orders_get", store_id=S, order=O)
   for s in order["supplies"]:
       r = sa.call("supplies_cargoes_set", {"store_id": S, "order": O, "supply": s["supply_id"],
                                            "body": bodies[s["supply_id"]],
                                            "idempotency_key": seller_ai.key("<метка запуска>", s["supply_id"])},
                   wait=True)
       print(s["supply_id"], seller_ai.outcome(r), sa.warnings)
   ```

   Ошибки — исключения `seller_ai.CliError` (`.code` — код выхода, `.body` — ответ сервера).
5. Долгая серия (квоты Ozon, сотни команд) — в фоне с выводом в файл; читать только хвост. Прервалось — тот же запуск с
   той же меткой: сделанное ответит прежней операцией (`replayed`), уйдёт только несделанное.
6. Отчёт — по итогам `--wait` (`succeeded` и ошибки по объектам), не по «отправлено».

## Чего нет и в CLI

Только на сайте, как и в MCP: вход и пароль, токены и доступы OAuth, приглашения и участники, создание магазина и ключи
Ozon, создание и правка групп магазинов. Прямого вызова API Ozon нет.
