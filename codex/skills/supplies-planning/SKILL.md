# Планирование поставок FBO

Чтения из зеркала Seller AI — ничего не меняют. Создание заявки по результату — навык `supplies-create`.

Общее: ответ с `sync_pending`, `coverage.postings_complete: false` или `warnings` — данные неполные: сказать это, не
считать нулём; `ads: null` — аналитика остатков Ozon ещё не прочитана (Ozon пересчитывает её ночью), статуса и
рекомендации тогда нет. 409 `not_ready` — раздел ещё загружается.

## Что и куда везти — `supplies_planning_availability`

Параметры: `view=clusters` (кластер → товары) или `products` (товар → кластеры); `days` — 7 / 14 / 28 / 56 («на сколько
дней должно хватить», 28 по умолчанию); `include_requested=true` — вычесть товар в заявках; `status` — `urgent`, `soon`,
`first_supply`; `search`, `skus`, `cluster_ids`, `liquidity`, `zones`; группы приходят без строк — строки по `expand`
(ключи групп или `all`); `sort` (`recommended_supply` по умолчанию), страницы.

| Поле | Значит |
|---|---|
| `status` | `urgent` «Срочно поставить» — остатка с товаром в пути меньше чем на 28 дней по ADS Ozon; `soon` — меньше 56; `enough` — 56–120; `do_not_supply` — ADS 0 или запас больше 120; `first_supply` — карточка не старше 77 дней, в кластере нет остатка, пути, продаж за 14 дней и заявок |
| `recommended_supply` | формула кабинета: `max(0, ⌈ADS × days − доступно − в пути [− в заявках]⌉)`; «нейросеть» кабинета в Seller API нет |
| `ads` | среднесуточные продажи Ozon за 28 дней, шт (в кластере — `ads_cluster`) |
| `available_fbo`, `available_fbs`, `in_transit`, `requested` | доступно FBO; свободный FBS-остаток складов продавца, отгружающих в кластер; в пути на склад Ozon; в заявках |
| `days_left_fbo`, `days_left_fbs`, `days_without_sales` | дней до конца остатка, дней без продаж |
| `liquidity` | ликвидность Ozon (`turnover_grade`): дефицитный < 28 дней, очень популярный 28–56, популярный 56–120, избыточный > 120 |
| `local_share` | доля локальных продаж кластера за 14 дней |

Важно: товар, отгруженный продавцом и лежащий **на точке отгрузки**, в `in_transit` не входит — рекомендация может
предложить его повторно. Проверить заявки `supplies_items_list` (`sku`, `states=ACCEPTED_AT_SUPPLY_WAREHOUSE`) и сказать.
В `unavailable` — чего в Seller API нет: «Упущенные продажи», «Дней без остатка», продажи в рублях, рекомендации
нейросети, «Поставка недоступна».

Ответ пользователю: срочные товары по кластерам (город, запас в днях, рекомендуемая поставка), с какого горизонта считано
и учтены ли заявки. Детальные счётчики остатков по складам (брак, излишки, вывоз, в заявках) — `stocks_fbo_list`
(`view=products|clusters`, `search`, `cluster_ids`).

## Локальность продаж — `supplies_planning_locality`

Доля локальных продаж — единицы отправлений FBO и FBS, отгруженных из того же кластера, куда доставлены, ко всем (от
«Готов к отгрузке»), за период (по умолчанию 14 дней до сегодня, не больше года). `view`: `clusters` (кластеры доставки),
`products`, `directions` (кластер отгрузки → кластер доставки, `share_of_delivery`); `scheme` `all|fbo|fbs`; фильтры
кластеров — по ID (`delivery_cluster_ids`, `shipping_cluster_ids`: в названиях есть запятые); `expand` для строк. Строки
несут `recommended_supply` на 28 дней в кластер доставки. `summary.share` — доля магазина, `daily` — по дням.

Низкая доля у кластера доставки и крупное направление «Москва → <город>» — повод везти товар в этот кластер: товар едет
к покупателю издалека, дольше и дороже. «Переплату за логистику», её причины и уровень доли Seller API не даёт.

## Среднее время доставки

Методы среднего времени доставки Ozon убрал из Seller API 19.05.2026, поэтому ни часов доставки, ни «% к базовому тарифу
логистики FBO», ни переплаты за логистику Seller AI не показывает. Сказать это и ответить через локальность: доля
локальных продаж и направления показывают, откуда товар едет к покупателю; чтобы ускорить доставку — размещать товар в
кластерах, куда он продаётся (поставки по `recommended_supply` в кластеры с низкой долей). Сами часы и надбавку — в
кабинете Ozon («Аналитика → География продаж → Среднее время доставки»).

## Продажи по кластерам — `supplies_planning_sales_by_clusters`

Заказанные штуки (FBO + FBS, все статусы; FBO — по дате создания, FBS — по началу обработки; дни Москвы) как сводная
«кластер отгрузки × кластер доставки» с итогами и рядом по дням. `period`: `today`, `yesterday`, `week` (по умолчанию),
`month` (30 дней), `quarter` (90), `year` (365) или `date_from`/`date_to`; `scheme`, `search`, `skus`; товары кластера
отгрузки — `expand`. `delivery_clusters[].units` / `totals.units` — свой «рынок» магазина по кластерам доставки
(можно передать как доли рынка в план поставки, навык `supplies-create`).

## «Точность отгрузок» — `supplies_accuracy_get`

Показатель за 28 полных дней Москвы до сегодня: ⌊100 × количество при отгрузке ÷ наибольшее количество после выбора
таймслота⌋, отменённая или непривезённая поставка — 0, виртуальные не считаются; порог Ozon — 10 %. `rate_percent: null`
— показателя нет (не 100 %); `basis: last_known` — в окне поставок нет, значение последнего окна за полгода;
`estimate.estimated` — часть оценена, пока журнал Seller AI не покрывает окно (`exact_from` — когда станет точным);
`supplies[]` — расшифровка (событие, дата, при отгрузке, максимум, источник). Ниже 10 % Ozon ограничивает переносы
таймслота (2 на заявку), объём поставки в кластер, создание заявок без таймслота и отмены резервных поставок; действуют ли
ограничения сейчас, Seller API не говорит — называть правило. Рекомендации — `recommendations`: выбирать таймслот, когда
состав и грузоместа готовы; не уменьшать состав и не отменять после выбора слота; привозить заявленное целиком.
