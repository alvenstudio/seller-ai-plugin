# Планирование поставок FBO

Только чтения — ничего не меняют. Подать заявку по результату — навык `supplies-create`.

Данные неполные — сказать это, не считать нулём:
- `ads: null` — Ozon ещё не дал аналитику остатков (пересчитывает её ночью): статуса и рекомендации нет;
- предупреждение «Остатки ещё загружаются…» или `coverage.postings_complete: false` — выборка неполная;
- пока грузятся отправления одной схемы, локальность и продажи по кластерам считают другую — `scheme` и предупреждение
  называют её: «пока только по FBO»;
- 409 `not_ready`: у локальности и продаж по кластерам не загружена ни одна схема, у «Точности отгрузок» ещё грузятся
  заявки.

## Что и куда везти — `supplies_planning_availability`

`view=clusters` (кластер → товары) или `products` (товар → кластеры); `days` — на сколько дней должно хватить (по
умолчанию 28); `include_requested=true` — вычесть товар в заявках. Группы приходят без строк: строки — через `expand`
(ключи групп или `all`).

- `status`: `urgent` «Срочно поставить» — остатка с товаром в пути меньше чем на 28 дней по ADS; `soon` «Скоро
  поставить» — меньше 56; `first_supply` «Поставить впервые» — карточка не старше 77 дней, в кластере ни остатка, ни
  пути, ни продаж за 14 дней, ни заявок; `enough` — 56–120 дней; `do_not_supply` — продаж нет или запаса больше чем на
  120.
- `recommended_supply` — формула кабинета `max(0, ⌈ADS × days − доступно − в пути [− в заявках]⌉)`; рекомендаций
  «нейросети» в Seller API нет. `ads` — среднесуточные продажи Ozon за 28 дней, шт. `liquidity` — ликвидность Ozon:
  дефицитный < 28 дней, очень популярный 28–56, популярный 56–120, избыточный > 120.
- **Товар на точке отгрузки** (продавец отгрузил, Ozon ещё не принял) в `in_transit` не входит — рекомендация может
  предложить его повторно. Проверить `supplies_items_list` (`sku`, `supply_states=ACCEPTED_AT_SUPPLY_WAREHOUSE` — статус
  поставки; `states` — статус заявки, у частично отгруженной он уже другой) и сказать.
- Чего нет в Seller API («Упущенные продажи», «Дней без остатка», продажи в рублях) — перечислено в `unavailable`: так и
  сказать.

Ответ: срочные товары по кластерам — город, запас в днях, рекомендуемая поставка; на сколько дней считано и учтены ли
заявки. Подробные счётчики остатков по складам (брак, излишки, вывоз, в заявках) — `stocks_fbo_list`
(`view=products|clusters`, `search`; его `cluster_ids` — свои ID кластеров (`cluster_id`), не ID из планирования).

## Локальность продаж — `supplies_planning_locality`

Доля штук FBO и FBS, отгруженных из того же кластера, куда доставлены; по умолчанию 14 дней до сегодня, не больше года.
`view`: `clusters` (кластеры доставки), `products`, `directions` (кластер отгрузки → кластер доставки,
`share_of_delivery`); `scheme` `all|fbo|fbs`; кластеры фильтровать по ID (`delivery_cluster_ids`,
`shipping_cluster_ids`) — в названиях есть запятые; строки — через `expand`. Строки несут `recommended_supply` на 28
дней в кластер доставки.

Низкая доля у кластера доставки и крупное направление «Москва → <город>» — повод везти товар в этот кластер: к
покупателю он едет издалека, дольше и дороже. Переплату за логистику, её причины и уровень доли Seller API не даёт.

## Среднее время доставки

Часов доставки, «% к базовому тарифу логистики FBO» и переплаты за логистику в Seller API нет: сказать это и ответить
через локальность — откуда товар едет к покупателю; ускорить доставку — размещать товар в кластерах, куда он продаётся
(поставки по `recommended_supply` в кластеры с низкой долей). Сами часы и надбавка — в кабинете Ozon: «Аналитика →
География продаж → Среднее время доставки». Наценка за нелокальную продажу — 0 % для всех кластеров с 09.07.2026 (навык
`unit-economics`); правила локальности и исключений — навык `ozon-edu`.

## Продажи по кластерам — `supplies_planning_sales_by_clusters`

Заказанные штуки FBO + FBS (все статусы, дни Москвы): сводная «кластер отгрузки × кластер доставки» с итогами и рядом по
дням. Период — `period` (по умолчанию неделя) или `date_from`/`date_to`; товары кластера отгрузки — `expand`.
`delivery_clusters[].units` / `totals.units` — свой «рынок» магазина по кластерам доставки: годится как доли рынка для
плана поставки (навык `supplies-create`).

## «Точность отгрузок» — `supplies_accuracy_get`

Показатель за 28 полных дней, порог Ozon — 10 %, методика — в `method`. `rate_percent: null` — показателя нет (не
100 %); `basis: last_known` — в окне поставок нет, это последнее значение за полгода; `estimate.estimated` — часть
оценена, пока журнал Seller AI не покрывает окно (`exact_from` — когда станет точным); `supplies[]` — расшифровка по
поставкам. Ниже 10 % Ozon может ограничить переносы таймслота (2 на заявку), объём поставки в кластер, создание заявок
без таймслота и отмену резервных поставок; действуют ли ограничения сейчас, Seller API не говорит — называть правило.
Советы — из `recommendations`; как правки заявки влияют на показатель — навык `supplies-orders`.
