# Грузоместа поставки FBO

`supplies_cargoes_set` меняет места одной поставки (`mode`):
- `replace` (по умолчанию) — полный набор: все места заменяются, у всех новые номера, прежние этикетки недействительны,
  «Годен до» вводится заново (без него пропадёт у всех мест). Для первого заполнения и полной переделки.
- `add` — новые места рядом с прежними: прежние сохраняют номера, этикетки и «Годен до».
- `delete` — удалить выбранные места (`cargo_ids`, не все): остальные остаются как были.

Состав поставки меняет отдельная команда — `supplies_supply_items_set`. Раскладку и тела команд считает
`scripts/cargo_plan.py` по ответу `supplies_orders_get`.

**Этикетки уже выданы — места не перезаливать (`replace`):** напечатанные этикетки станут недействительны. Точечные
правки — `add`/`delete`; новый полный набор — только по просьбе, и тогда «распечатайте новые».

## Что читать

`supplies_orders_get` по `order_id` (номер вида `12345678-1` → `supplies_orders_list` `search`): `supplies[].bundle_id`
— это `expected.bundle_id` правки состава, `supplies[].cargo_ids` — `expected.cargo_ids` правки мест, `cargoes[]` —
места (`cargo_id` — 16 цифр, `1022…`, виден на этикетке; `items[]` — состав места), `packing` — `units_per_box`
черновика (готовый `box_size`), если заявку подавал Seller AI. `checklist.items[].done: null` — синк ещё не прочитал
места: так и сказать, мест не «ноль».

## Команда `supplies_cargoes_set`

`order`, `supply`, `body: {mode, cargoes: [{type, items: [{sku, quantity, expires_at}]}], cargo_ids, expected:
{cargo_ids}}`.

- Не больше 30 коробок и 40 палет в поставку (или лимита поставки; с `add` считаются и прежние места) — иначе 422
  `cargo_limit`: остаток — отдельной заявкой (навык `supplies-create`), палеты ради лимита не вводить.
- В местах — только SKU поставки, кратно кванту и не больше её количества; меньше можно, но приёмка станет платной
  (`not_fully_distributed`).
- `expires_at` — «годен до», `YYYY-MM-DD`. Ozon его принимает, но не отдаёт ни одним чтением и не печатает на этикетке:
  подтверждается только состав мест, срок пользователь сверяет в кабинете — так и сказать.
- `expected.cargo_ids` — живые места, которые видел пользователь (у поставки без мест — `[]`); не совпало — 409
  `stale_expected` с `current`: перечитать и показать. 409 `cargoes_not_settable` — поставка уже не
  `DATA_FILLING`/`READY_TO_SUPPLY` (`IS_FINALIZED` — места не меняются).
- Полная просьба — фасовка и срок («заполни грузоместа: 40 коробок по 12, срок 25.02.2027»): отправить и показать
  раскладку. Чего-то нет или раскладка расходится с просьбой (недобор, неполная коробка, которой пользователь не ждал) —
  спросить один раз.
- Одна поставка — одна команда; заявку из 19 поставок — 19 команд по очереди, итог каждой проверять. Готово — когда
  набор мест в чтении совпал с отправленным.

## Заполнить места

`python3 scripts/cargo_plan.py layout in.json` → `body` (в `supplies_cargoes_set`) и `summary` (для показа):
- одна фасовка — `{"sku", "quantity", "box_size", "pallet_size" | null, "expires", "expected_cargo_ids"}`: целые палеты,
  остаток коробками, последняя коробка неполная; без `pallet_size` палет нет;
- точная раскладка — `"breakdown": {"20": 30, "12": 5}` («штук в месте: мест», от 100 шт — палета), сумма = количеству
  поставки;
- разные сроки по размерам — `"expires": {"12": "2027-02-25", "10": "2027-02-27"}`; нет срока какого-то размера — скрипт
  остановится до команды;
- `expected_cargo_ids` — нынешние места поставки (`supplies[].cargo_ids`), у новой поставки `[]`.

До команды сверить по городам количество, коробки и палеты, неполную коробку, недобор против плана. Совпало с просьбой —
заполнить и показать в отчёте; расходится — показать и спросить один раз. Состав и места — до таймслота (навык
`supplies-orders`).

## Округлить поданную заявку по коробкам

«12345678-1 округли по коробкам и заполни: 70 коробок по 12 шт, срок 25.02.2027; 26 по 10, срок 27.02.2027». Это не
перераспределение по продажам: пропорции заявки сохраняются, **все названные коробки расходятся** — объём = сумма
коробок (70 × 12 + 26 × 10 = 1100 шт, сколько бы ни было в заявке), про кратность не спрашивать. У поставки коробки
одного размера — и один срок; минимум коробка на поставку (поставка на 2 шт вырастет до коробки).

1. `supplies_orders_get` → поставки и количества. План — `python3 scripts/cargo_plan.py boxplan in.json` с `{"supplies":
   [{supply_id, quantity}], "inventory": {"12": 70, "10": 26}, "expires": {"12": "2027-02-25", "10": "2027-02-27"}}`
   (одна фасовка без числа коробок — `"box_size": 12`: объём до целых коробок). Поставки на 0–1 шт в план не входят (к
   отмене). По одному размеру не разложилось («задайте раскладку сами»): срок у всех размеров один — `"allow_mixed":
   true` (размеры смешаются, `mixed: true`); сроки разные — раскладку задаёт пользователь.
2. Таблица: город, было, станет, коробки, размер, срок. Названы коробки и срок каждого размера — это согласие:
   выполнять, таблицу — в отчёт. Нет срока какого-то размера или скрипт не разложил — спросить один раз. Пропорции не
   нравятся — пересчёт по продажам (навык `supplies-create`); но поставку с коробками двух размеров и двумя сроками не
   заполнить.
3. Состав — `supplies_supply_items_set` по каждой поставке значением из плана (не набирать руками — путаются города),
   `expected.bundle_id` — из свежего чтения. Поднять можно, только пока у поставки нет мест (иначе `INBOUND_NO_CAPACITY`
   — сказать и спросить); у заявки со слотом рост — `raises_maximum` (навык `supplies-orders`). Ozon срезал — места этой
   поставки `python3 scripts/cargo_plan.py layout in.json` по факту (`quantity`, `box_size` её размера): полные коробки
   и одна неполная.
4. Места — `layout` с `breakdown` поставки из плана и сроком её размера → `supplies_cargoes_set` (`replace`).
5. Этикетки — новые у всех мест: набор по видам мест («Этикетки»), по PDF на размер коробки.
6. Сверка — `python3 scripts/cargo_plan.py check in.json` («Приёмка бесплатная?»): итог = сумма коробок минус срезанное
   Ozon. В отчёте — у каких городов какие коробки и срок; срок пользователь сверяет в кабинете.

## Найти, убрать или добавить грузоместа

**Убрать место — не значит уменьшить поставку.** Убрали 2 коробки по 8 шт — в местах на 16 шт меньше, а в заявке прежнее
количество: Ozon увидит недовоз и возьмёт плату. Поэтому правка — всегда пара команд: убрать — **места → состав**,
добавить — **состав → места**.

- **Найти.** Номер с этикетки (16 цифр, `1022…`) → `supplies_orders_list` `search=<cargo_id>` — сразу заявка с этим
  местом; показать её ссылкой, город, состав места. Не нашлось — `supplies_orders_get` по заявкам вкладки `preparation`,
  пока не найдётся (заявку пользователь знает — начать с неё). Нет ни в одной — сказать прямо, похожую этикетку не
  подсовывать.
- **Убрать.** `python3 scripts/cargo_plan.py remove in.json` с `{"order": <ответ supplies_orders_get>, "cargo_ids":
  [...]}` → по поставке `cargoes_body.body` (`mode: delete`) и `items_body` (состав: было − убранное). Просьба с
  номерами мест — согласие; удалённое место не вернуть. Сначала `supplies_cargoes_set` с `cargoes_body.body`; после
  `succeeded` перечитать заявку и `supplies_supply_items_set` с `items_body` (`expected.bundle_id` — из свежего чтения).
  Наоборот нельзя: не пройдёт удаление — мест останется больше состава, а поднять состав у поставки с местами Ozon не
  даёт. Отчёт: «48 − 16 = 32 шт».
- Все места поставки удалить нельзя (`cant_delete_all`, скрипт тоже откажет) — только новый полный набор: `layout` →
  `replace`, срок годности спросить.
- **Добавить.** `python3 scripts/cargo_plan.py add in.json` с `{"order", "supply_id", "sku", "places": [{type,
  quantity}], "expires"}` (срок новых мест) → сначала состав (`items_body`), потом `supplies_cargoes_set` с
  `cargoes_body.body` (`mode: add`). Поднять состав у поставки с местами Ozon не даёт (`INBOUND_NO_CAPACITY`) — тогда
  добавочный объём только новой заявкой.
- `keep_quantity: true` (места без правки состава) — почти всегда платная приёмка: только по явной просьбе.
- После таймслота уменьшение состава снижает «Точность отгрузок»: `supplies_supply_items_set` попросит
  `confirm_accuracy` (навык `supplies-orders`); при многих правках сказать об этом.

## Приёмка бесплатная?

`supplies_cargo_rules_get` по заявке → по поставке `rules[]` (`rule`, `applicable`, `required`, `satisfied`) и
`done`/`total` («Подготовка к приёмке — выполнено N из M»). Кэша нет: читать после каждой подтверждённой правки мест.
Правила: `is_valid_distribution` — состав мест совпадает с заявкой (**главный флаг платности**); `cargoes_presents` —
места заполнены; `package_units_with_distribution` — у мест указан состав; `placement_zones` — в коробке товары одной
зоны размещения; `expire_dates_presented` — сроки указаны (факт, не дата); `edit_deadline_expire` — срок правок истёк.
Первые два учитывать всегда, прочие — только `applicable` и `required`: иначе верная поставка окажется «платной» из-за
неприменимого правила.

Сверка — `python3 scripts/cargo_plan.py check in.json` с `{"order": <ответ supplies_orders_get>, "rules": <ответ
supplies_cargo_rules_get>, "expected": {supply_id: штук по плану или по факту после среза}}` (`rules` и `expected` — по
желанию): `rules_ok: null` — правила поставки не прочитаны (не «бесплатно»); `single_unit` — 1 шт: поставка к отмене в
кабинете, если её не везут, иначе ложная тревога.

- Все учитываемые правила выполнены — «условия бесплатной приёмки выполнены».
- `is_valid_distribution` не выполнено — **починить до отгрузки**: состав поставки привести к штукам в местах
  (`supplies_supply_items_set`, вниз проходит всегда); везти больше — места новой заявкой, а не поднимать количество.
- Правила не прочитались — не называть приёмку бесплатной, перечитать.

Прогноза суммы приёмки нет ни в Seller AI, ни в API Ozon: «0 ₽» — только в смысле «условия бесплатного тарифа
выполнены». Цена расхождений по тарифам Ozon — [references/acceptance-pricing.md](references/acceptance-pricing.md).
Факт — после приёмки: `finance_accruals_list` с `search=<supply_id>` и `search_scope=all` — строки приёмки и обработки
поставки; строк ещё нет — «не начислено», не 0.

## Этикетки

Этикетки — у подтверждённых мест: после `replace` — все заново («распечатайте новые»), после `add` — этикетки новых мест
(«Выбранные места»). Срока годности на этикетке нет.

**По видам мест — основной путь** (заявка, поставка из нескольких заявок, места одного размера):
1. `supplies_cargo_labels_bundles_create`, `body: {supplies: [{order_id, supply_id, cargo_ids}]}` — 1–300 поставок, до
   2 000 мест (больше — наборы по заявкам). Без `cargo_ids` — все живые места поставки, с ними — только эти. `names:
   {<sku>: «<название с весом>»}` — когда пользователь называет товар иначе, чем карточка. Один `idempotency_key`. Ответ
   — 202 с `bundle_id`; `503 orders_loading` — заявки ещё дочитываются: тот же вызов через `retry_after`.
2. `supplies_cargo_labels_bundles_get` (`bundle`): 202 `working` — повторить через `retry_after`; 200 `ready` —
   `files[]` и `missing`; `failed` — файла нет: сказать почему. `parts.done` не растёт 10 минут — сказать и выдать
   этикетки по поставкам (ниже).
3. Каждый файл — `supplies_cargo_labels_bundles_file` (`bundle`, `file`). Один PDF на вид места (тип × штук в месте) по
   всем поставкам: «<товар> <N> коробок по <X> шт.pdf» / «<товар> <N> палет по <X> шт.pdf». **Все файлы — пользователю
   сразу, имена не менять.** `missing` — места без этикеток и причину назвать прямо. Набор живёт сутки, позже — новый
   набор.

**Одна поставка — запасной путь**: `supplies_cargo_labels_download` (`order` — `order_id` цифрами, не номер «…-1»;
`supply`) → PDF, отдать как есть. Пока Ozon готовит, ответ — JSON с `task_id`: через несколько секунд тот же вызов с
этим `task_id`. Несколько поставок — по одной, не параллельно и не пока работает набор (общая квота Ozon); 429 —
следующий вызов через `retry_after`.

**Выбранные места** (новые места после `add`, одно место по фото этикетки) — если у заявки
`capabilities.selected_cargo_labels: true`: `supplies_cargo_labels_create` (`order`, `supply`, `body: {cargo_ids}` —
1–100 живых мест этой поставки, одно задание — один PDF) → 202 `{job_id, retry_after}` → через `retry_after`
`supplies_cargo_labels_selected_download` (`order`, `supply`, `job`), пока вместо 202 не придёт PDF.
`label_creation_unknown` — не повторять; `label_creation_rejected` — Ozon отказал: назвать причину; 422 — номера не этой
поставки или не живые: перечитать заявку.

`label_file_unavailable` (одна поставка, выбранные места) — файл Seller AI недоступен: этикетки — на вкладке
«Грузоместа» кабинета (`cabinet_url`).

Сверить страницы с местами: у набора `pages` = `places` каждого файла и N в имени (расхождение — в `warnings` файла); у
одной поставки — с `cargo_totals`; у выбранных мест — с числом `cargo_ids` (страницы PDF посчитать локально: pypdf,
`len(PdfReader(файл).pages)`).

## Как говорить с пользователем

Заявка ссылкой, город, коробки и штуки, сколько осталось в заявке, бесплатна ли приёмка. Номера грузомест называть можно
— пользователь читает их с этикеток. `supply_id`, `bundle_id`, `operation_id`, коды правил не показывать; причину
платности — цифрами («в местах 24 шт, в заявке 32»).
