# Товарная этикетка

Этикетку рисует Seller AI: `products_labels_create` собирает поля и отвечает, что напечатано и откуда, `products_labels_file`
отдаёт PDF. Ничего не меняется ни в Ozon, ни в магазине. На сайте то же самое — «Товары → Этикетки».

## Порядок

1. **Товар.** `stores_list` → `store_id`. Потом `products_list` с `search` по словам пользователя: название, артикул, SKU или
   штрихкод.
   - Несколько кандидатов — показать их и спросить.
   - Одно название в двух фасовках — взять ту, чей вес назван, двойника назвать.
   - Карточки нет — разовая этикетка без `product_id`: все поля из слов пользователя.
2. **Этикетка.** `products_labels_create`. В теле:
   - `product_id`;
   - `packing_date` (ГГГГ-ММ-ДД) — дата из последней фразы пользователя;
   - всё, что пользователь назвал сам.

   Остальное Seller AI берёт сам:
   - **Тексты** — состав, КБЖУ, срок, хранение, страна: из характеристик карточки, иначе из сохранённых полей товара.
   - **Заголовок** — сохранённый, иначе название карточки заглавными. Короткий («КУРАГА БЕЗ САХАРА») — `title`, пустой —
     без заголовка.
   - **Масса нетто** — из названия карточки.
   - **Штрихкод** — первый EAN-13 карточки.
   - **Юрлицо** — владелец магазина. Имя и ИНН из данных Ozon, адрес и телефон из «Реквизиты для этикеток».
   - **Тип** — «Упаковано».
3. **Проверка ответа.** `fields` — что напечатано, `sources` — откуда взято.
   - Строки `warnings` назвать пользователю: какой штрихкод взят из нескольких, какой код не EAN-13 и не выведен, чего
     нет, расхождение массы, текст карточки поверх сохранённого.
   - Нет адреса или телефона владельца — спросить один раз. Сохранить `stores_label_entities_save`
     (`{"owner": true, "address": "…", "phone": "…"}`) и повторить шаг 2. Адрес не выдумывать.
   - Нет состава, срока или хранения — взять у пользователя и передать полями запроса.
4. **Файл.** `products_labels_file` с `label` — это `label_id` ответа — даёт PDF. Отдать пользователю, имя — `file_name`.
5. **На следующий раз.** Предложить сохранить то, что пользователь назвал и чего нет в карточке:
   `products_label_settings_save` с `product`; поля те же, что у запроса, `null` — убрать. Просьба «запомни» — уже согласие.

## Поля запроса

| Поле | Когда |
|---|---|
| `label_type` | `packer` «Упаковано» (по умолчанию), `manufacturer` «Производитель», `maker` «Изготовитель», `barcode_only` — заголовок и крупный штрихкод |
| `size` | `58x40` (по умолчанию) или `58x60` |
| `title` | короткий заголовок заглавными; `""` — без заголовка |
| `composition`, `kbzhu` `{protein, fat, carbs, calories}`, `shelf_life`, `storage_conditions`, `country`, `weight` | значения из чата — поверх карточки; масса как напечатать: «400 г», «0,45 кг ± 0,02 кг» |
| `show_country`, `show_packing_date` | `false` — без страны, без даты |
| `font_bold` | `title_only` (по умолчанию), `all`, `none` — «жирность меньше» |
| `copies` | страниц в PDF, одна этикетка на каждой (до 500) |
| `entity_id` / `entity` | другой упаковщик: сохранённый (`stores_label_entities_list`) или разовый `{legal_entity, inn, kpp, address, phone}` |
| `barcode` | EAN-13 вместо кода карточки; `""` — без штрихкода; `"new"` — новый код |

## Штрихкод

- **Как выбирается.** Печатается первый годный EAN-13 карточки: 13 цифр с верной контрольной цифрой или 12 цифр, к которым
  контрольная дописывается. Коды `OZN…`, 9-значные и с неверной контрольной цифрой не печатаются, ответ это называет.
- **Код другого товара.** «ШК возьми из магазина X» — найти карточку X по названию и весу и передать её EAN-13 в
  `barcode`. У каждого веса свой код.
- **Кода нет.** `barcode: "new"` даёт новый EAN-13 с префиксом 200, которого нет ни у одной карточки магазина.
  - Привязать его к карточке — `products_barcodes_add`: `{"items": [{"product_id": "…", "barcode": "<код>"}]}`, право
    `products: write`.
  - «Сделай этикетку и привяжи код» — уже согласие. Без этого спросить и сказать: непривязанный код склад не опознает.
  - Готово, когда операция `succeeded`, до 15–20 минут.
- **Код Ozon `OZN…`.** `products_barcodes_generate` делает такой код — это не EAN-13, на эту этикетку он не попадёт.

## Лист Ozon «Ozon Seller.pdf» (коды OZN)

Пользователь прислал лист Ozon и просит «добавь состав, срок, дату». Два пути — назвать оба, если он не выбрал:

1. **Своя этикетка с EAN-13** — порядок выше. Новый код привязать к карточке, иначе склад товар не опознает.
2. **Оставить штрихкод Ozon** — только у агента, который запускает код. Растр страницы 600 dpi:
   `pdftoppm -png -r 600 -f N -l N`. Блок штрихкода с цифрами вырезать без изменения ширины и поставить наверх этикетки,
   текст ниже:

   ```bash
   python3 scripts/ozon_sheet_to_label.py --png sheet-1.png --dpi 600 --crop x,y,ширина,высота --data data.json --out label.pdf
   ```

   В `data.json` — поля текста: `title`, `label_type`, `legal_entity`, `inn`, `address`, `phone`, `composition`, `kbzhu`,
   `shelf_life`, `storage_conditions`, `weight`, `country`, `packing_date`. Их взять из ответа `products_labels_create`
   этого товара (`fields`). Блок шире этикетки — ошибка, `--fit` сжимает. После рендера проверить пробную печать сканером.

## Тонкости

- **Даты.** Сверять с сегодняшней датой по Москве. Названный «срок» уже в прошлом — почти наверняка это дата упаковки:
  уточнить одним вопросом, просроченную этикетку не печатать.
- **Образец.** Присланный образец задаёт формулировки: тип надписи, формат массы, состав и реквизиты дословно. Вёрстку
  он не задаёт — она у Seller AI одна.
- **Противоречия карточки.** Страна против состава, холодильник для сухофруктов, вес в артикуле против названия — молча на
  этикетку не переносить. Назвать и предложить поправить карточку.
- **Без карточки.** Состав и КБЖУ «из интернета» — только по прямой просьбе и с пометкой «сверить с упаковкой
  поставщика».
- **Двойная этикетка FBS.** Товарная и FBS на одном листе — навык `fbs-orders`. Он берёт PDF отсюда.
